# Mac 전용 대화 검토

`kiryu_ai.chat_admin`은 채팅 API와 다른 포트에서 여는 소유자 화면이다. 공개 Worker·Tunnel의 전달 목록에 포함하지 않는다. Gemma를 따로 실행하거나 입력을 생성하지 않고 같은 SQLite 원문과 검토 기록을 읽는다.

```sh
PYTHONPATH=ai python -m kiryu_ai.chat_admin \
  --database references/local/chat/state/chat.sqlite3
```

기본 주소는 `http://127.0.0.1:8767/`이며 다른 인터페이스에 bind하는 옵션은 없다. 터미널의 일회용 링크를 Mac 브라우저에서 연다. 이 링크는 방문자용 주소가 아니며 공유하지 않는다. 링크 fragment는 첫 요청 전에 주소창에서 제거되고, bootstrap을 교환한 후 HttpOnly·SameSite=Strict 소유자 쿠키로 동작한다. 세션은 8시간이며 서버 재시작·검토 종료 후에는 새 실행의 일회용 링크가 필요하다.

별도 `admin-signing.key`는 DB와 같은 비공개 디렉터리에 권한 600으로 저장된다. 정확한 Host와 Origin(포트 포함), 소유자 서명, 변경 요청의 CSRF 값을 확인한다. CORS는 허용하지 않는다. HTML/응답은 no-store, CSP, frame 차단, no-referrer를 사용한다. 관리자 API 오류에 대화나 upstream 예외 원문을 출력하지 않는다.

## 화면 사용

- 왼쪽은 검토할 답장 목록이다. 실패·잘림, 20초 초과, 미검토 순으로 정렬한다. 인물·방문자·본문·한국 시간 날짜 범위·모델·프롬프트를 좁히거나 현재 조건에서 무작위 표본을 확인할 수 있다.
- 가운데는 선택한 답장 앞뒤의 원문이다. 전체 대화로 확장할 수 있다. 실패 생성은 정상 답장과 다른 색과 문구로 표시한다. 원문을 고치는 기능은 없다.
- 오른쪽에서 말투, 판단, 관계·감정, 스토리·지식, 문맥·기억, 문자 형식을 각각 평가한다. 실제로 확인하지 않은 축은 미평가로 둔다. 태그·추정 원인·메모·개선 답안을 별도로 저장한다. 하단의 평가 저장/저장 후 다음 버튼은 스크롤해도 유지된다.
- 실제 실행 근거를 펼치면 당시 모델·프롬프트 버전, 입력 메시지 ID와 envelope, 입력 해시, 검색한 원작 장면·과거 원문, 완료/첫 토큰/대기 시간을 확인한다. 기존 JSON이 보관하지 않은 값은 미기록으로 남긴다.
- 기간·버전별 현황은 전체 사례 수와 검토 수를 함께 보여준다. 각 축의 문제 비율은 해당 축을 실제로 평가한 최신 검토의 표본 수를 분모로 사용한다. 미평가와 일부 아쉬움을 문제 있음으로 합치지 않는다.

다음/이전 미검토 버튼은 현재 목록에서 미검토 답장을 이동하며, 목록은 50개씩 나뉜다. 자동 정렬·지연 표시는 검토 우선순위일 뿐, 캐릭터 품질이나 팬 승인 판정이 아니다.

## 내보내기

목록의 체크박스로 선택한 사례만 JSONL로 내려받는다. 원문 앞뒤 문맥, 실패 출력, 검색 근거, 버전, 모든 검토 기록을 포함한다. 동일 사례는 한 번만 내보내며 최대 100개다. 세션·토큰 해시·관리자 비밀 테이블을 조회하지 않고 메타데이터의 알려진 비밀 필드도 제외한다.

내보내기와 검토의 `training_eligible`은 기본 `false`다. 높은 평가와 개선 답안 작성은 학습 승인으로 바뀌지 않는다. 검토·개선 답안·실패 출력도 모델 기억에 자동 편입되지 않는다.

## 검증 자료

`ai/tests/test_chat_admin.py`는 인증·일회용 bootstrap·Host/Origin·CSRF·쿠키 변조/만료/종료, 필터·정렬, 원문 불변, 여섯 축과 통계 분모, 선택 내보내기·비밀값 제외를 CPU에서 검사한다. `seed_fixture`는 관리자 화면 검증을 위한 명시적인 합성 자료이며 실제 Gemma 답변·원작 대사·팬 평가 자료가 아니다.

관리자 화면의 직접 캡처에는 합성 DB만 사용한다. 실제 방문자의 대화를 공개 PR 이미지나 저장소에 넣지 않는다. 일반 사이트의 iPhone 화면은 이 관리자 자산을 로드하지 않는다.
