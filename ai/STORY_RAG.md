# 원작 사건을 검색하고 읽는 방식

검토일 2026-10-28. 모델 학습 없이 기존 로컬 Gemma 4 26B-A4B IT Q4_K_M를 사용한다. 이 문서는 설계와 검증 방법이며 논문의 결과를 이 제품 성능으로 주장하지 않는다.

## 문제를 나누어 진단한다

자료가 없는 문제, 검색에서 놓친 문제, 입력 예산에서 밀린 문제, 근거를 읽고도 새 사실을 보탠 문제를 구분한다. 이전 실제 출력은 정확한 복귀 근거가 들어갔는데도 설득 강도·횟수를 상상했다. 따라서 검색만 변경하고 생성 정확성이 해결됐다고 판단하지 않는다.

원본 1,201개 청크(공략 838, 게임 목표 197, 백과 144, 공식 줄거리 18, 공식 제품 4)는 그대로 보존한다. 공략의 목표·명령, 홍보 줄거리의 미해결 전제를 완료 사건이나 최종 결말로 자동 변환하지 않는다. 실행 자료는 기존 31개 사실에 공식 출처 검토 21개를 더한 52개 사실과 4개 장면이다. 전 시리즈 모든 사건을 채택한 범위는 아니다.

LightRAG/GraphRAG의 넓은 주제 요약과 포괄성 평가는 짧은 한국어 문자의 원작 사실 정확성과 같지 않다. 현재 자료 규모에 그래프 프레임워크를 도입하기보다 근거가 없는 구간과 읽기 오류를 먼저 측정한다.

원문 스냅샷은 `references/local/gemma-chat/rag-research/primary-sources/index.json`에 URL·내용 SHA와 함께 보관한다. 외부 코드를 실행하거나 앱에 번들링하지 않는다.

## 실행 경로

1. 방문자/인물/시나리오와 자료 승인·분할 필터를 먼저 적용한다.
2. 현재 문자와 최근 두 교환을 각각 검색해 hybrid 후보를 섞는다. reader 후보에는 E5의 임의 절대점수 0.84를 적용하지 않고 상대순위 상위 결과를 제한한다. [E5 공식 FAQ](https://huggingface.co/intfloat/multilingual-e5-small#faq)의 점수 해석을 따르며, 후보 선정은 관련 사실의 승인이 아니다. 기본 12개, 검수된 같은 `event_id` 또는 `related_ids`만 최대 4개를 추가한다. 연결 확장에도 같은 권한 필터를 적용한다.
3. 읽기 단계에 현재 문자·최근 대화·관련 과거 원문 구간·핵심 관계·검색 후보를 구분해 제공한다. 사실의 `context`, 종류, 적용 범위와 정확한 출처 발췌를 함께 읽힌다.
4. 같은 로컬 모델이 짧은 JSON으로 최대 5개 근거 ID와 원문 필드(`text`/`source_excerpt`), 답변 초안, 현재 질문의 미확인 부분을 만든다. 모델이 문자열을 재작성하지 않고 코드가 선택한 필드의 원문을 그대로 인용에 채운다. 입력 후보 ID·필드·내용 존재를 검사한다. 없는 ID·허용되지 않은 필드·잘린 출력은 정상 답장이 되지 않는다.
5. 캐릭터 모델에는 `grounded`와 `conversation` 모두 `mode`와 선택 `notes`만 전달한다. 읽기 담당의 자유 초안(`answer`)·미확인 목록(`unknowns`)은 감사 기록에만 남기며 최종 생성 입력에 넣지 않는다. 선택된 원작 ID에는 정확한 인용과 함께 해당 자료의 전체 검수 `text`·`fact_type`·`scope_note`를 `source_snapshot`으로 붙인다. 핵심 관계 ID에도 같은 규칙을 적용하고, 동적 사실 목록이나 검색 기록에 관계 항목을 중복 추가하지 않는다. 대화 인용의 역할·시간과 원문·정정 구간은 함께 보존한다. 캐릭터 모델이 이 근거와 실제 대화를 읽고 인물 카드에 따라 답장을 작성한다.

읽기 노트는 요청 단위 중간 자료다. 대화 기억이나 원작 DB에 확정 사실로 추가하지 않는다. 현재 방식은 자유 노트 초안을 답장에 전달하는 CoN 재현이 아니라 출처 선택 후 생성 변형이다. 자유 초안의 인칭·말투 오류 전파를 막지만 잘못된 근거 선택이나 최종 모델의 해석 오류까지 해결했다고 보지는 않는다. 내부 사고 토큰은 수집하지 않는다.

## 실행 설정과 감사

- 읽기: native Gemma template, thinking OFF, temperature 0, 출력 최대 1,024토큰, 입력 최대 4,096토큰, JSON schema 제약. 오래된 대화를 먼저 줄이고 최상위 근거를 보존한다. 원문 한 항목을 중간에서 자르지 않고 구간 단위로 제거한다. 선택한 대화 인용의 원문·정정 문맥은 최종 입력에도 함께 남긴다. 함께 담지 못하면 명시적으로 예산 오류를 기록한다.
- 답장: 기존 thinking ON, temperature 1.0/top-p 0.95/top-k 64, 입력 3,072/출력 3,072/전체 6,144토큰. 일반 문자 길이 지침 유지.
- 각각 동일 모델 슬롯을 순차 사용한다. 별도 모델 복사나 외부 추론 API는 없다. 읽기 시간까지 서비스 응답 시간에 포함한다.
- 읽기용 입력 SHA·짧은 노트·후보/제외/선택 ID·모델 설정을 생성 실행 메타데이터에 보존한다. 최종 입력 SHA와 source identity도 계속 기록한다. 읽기 시작부터 `generating` 상태와 단계별 입력·근거를 DB에 기록한다. 읽기 실패는 비공개 감사 결과와 함께 오류로 남기고 다른 모델이나 검증하지 않은 직접 답장으로 대체하지 않는다.
- 작품 시간선으로 원작 자료를 차단하지 않는다. 원작 설명의 상대시점(현재·앞으로·몇 년 전)은 작품 안의 표현이며 오늘의 IF 상태로 승격하지 않는다. 현재 IF의 이동·정정·취소 순서는 유지한다. 나팔꽃은 배경/초기 위치이며 고정 대화 주제가 아니다.

## 실제 내용 검증

`story-research-evaluation.json`은 새 출력 확인 전에 만든 4개 대화 × 3턴 + 단일 8개, 총 20조건이다. 구현과 작성자를 분리했지만 자료 작성자가 평가도 작성했으므로 외부 블라인드 평가가 아니다. 마지마에게 하루카 전용 자료를 요구하던 근거 목록 오류는 생성 전에 고쳤고 의미 기준은 바꾸지 않았다.

같은 확장 자료/모델/답장 샘플링/seed에서 `chat_evaluate --reading direct`와 `--reading separate`를 비교한다. 기존 38조건은 회귀 자료로 남기며 원래 오답과 설정 변경 실험도 삭제하지 않는다. 일부 같은 근거를 직접 주는 비교로 reader 오류를 분리한다.

- 자료 포함 여부, 검색 후보 포함, 최종 선택/예산 생존을 별도로 기록한다.
- 최종 답변은 사실·문맥·말투를 분리하고, 질문에 요구하지 않은 세부 생략을 사실 오류로 세지 않는다.
- 추가로 만들어낸 과거 사실·원인, 알려준 사실에 대한 불필요한 회피, 인물 관계 뒤바뀜, 정정/현재 위치 혼동을 기록한다.
- 새 방식은 답할 수 있는 내용을 유지하면서 근거 없는 추가 주장을 줄여야 채택한다. 불명확하면 성공으로 단정하지 않고 추가 진단한다.
- 팬 검토, 실제 iPhone Safari, 전 시리즈 지식 완성은 이 평가로 대신하지 않는다.

실제 수치·원문·독립 의미 판정은 `references/local/gemma-chat/rag-research/`와 연결 PR에 저장한다. 문서 작성만으로 검증을 통과한 것으로 기록하지 않는다.
