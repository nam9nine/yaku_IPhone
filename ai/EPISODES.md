# 볼링 사건 운영

사건 상태와 발신 순서는 Mac의 기존 SQLite DB가 관리한다. 브라우저는 활성 상태·표시 완료·통화 결과만 보고한다. 새 사용자의 첫 사건은 활성 사용시간 90초 뒤 준비하며, 사이트가 닫힌 시간을 누적하지 않는다.

## 기능 플래그와 배포 순서

기본값은 OFF다. API·Worker·새 Pages 클라이언트를 먼저 반영하고 `/v1/health`의 `episode_protocol: 1` 및 새 클라이언트의 인증된 사건 요청을 확인한다. 운영 기능을 켤 때만 API 실행 환경에 다음 값을 설정한다.

```sh
KIRYU_EPISODES_ENABLED=1 PYTHONPATH=ai .tooling/gemma/venv/bin/python -m kiryu_ai.chat_stack --cloudflared /opt/homebrew/bin/cloudflared
```

위 명령은 기존 전체 스택이 종료된 상태에서 사용한다. 이미 모델·API가 실행 중일 때 두 번째 스택을 띄우지 않는다. 개별 API만 재실행하는 운영 절차에서도 같은 환경 변수를 전달한다. 되돌릴 때는 값을 `0`으로 하여 API를 재시작한다. 일반 채팅과 이미 저장된 대화는 유지한다. 서버 재시작으로 중단된 추론은 정상 답장으로 복구하지 않는다.

DB를 처음 열면 schema 4로 이관한다. 반영 전 SQLite Backup API로 백업하고, 기존 DB를 덮어쓰거나 JSON을 다시 원본으로 바꾸지 않는다.

## 전달 경계

- 새 선제 문자는 OS 푸시를 발송하지 않는다. 일반 답장과 통화 후속 문자의 기존 정책은 유지한다.
- 사용자 입력 접수 시 같은 사건의 미완료 작업을 중단한다. 생성 중이던 출력은 모델 호출 종료 후 감사 기록에만 남길 수 있다.
- 사용자 입력보다 먼저 정상 저장된 초대는 원본 이력에 남는다. 화면의 지연 타이핑·알림만 억제하여 이미 저장된 문장을 뒤늦게 새 연락처럼 재생하지 않는다.
- 표시 완료는 읽음이나 방문자의 수락을 뜻하지 않는다. 약속·이동·결과는 실제 사용자 근거로만 갱신한다.
- 전화 claim·종료 결과는 사건 ID에 묶는다. 사건 전화는 기존 고정 종료 문자나 별도 후속 큐를 함께 사용하지 않는다.

## 검사와 한계

`ai/chat/bowling-evaluation.json`은 사전에 고정한 12개 상황이다. `python -m kiryu_ai.episode_evaluate`는 격리 DB에서 실제 모델·API·reader를 사용하고 출력과 입력 버전을 보존한다. 이 실행기의 가속된 활성 시계는 공개 사이트에서 실제 시간 흐름을 확인하는 검사를 대신하지 않는다.

팬 평가·실제 iPhone·공개 전달은 각각 관찰한 증거로 구분한다. 원작 참고 자료에 있는 니시다의 연락은 이번 방문자에게 실제로 온 연락으로 처리하지 않는다. 원작 한국어 대사로 검증하지 않은 생성 문장을 공식 대사로 표시하지 않는다.
