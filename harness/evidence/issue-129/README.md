## 발견한 오류와 변경

## v26 후보: 두 해석의 일치와 보류

실제 대화를 native user/assistant 입력으로 전달한 해석과, 같은 입력 끝에 고정된 일반 예시를 추가한 해석을 동일 모델에서 순차 실행한다. 원작 자료나 캐릭터 대사는 이 단계에 넣지 않는다. 두 결과의 엄격한 검증과 사건 ID·버전·결정·근거 ID 전체가 일치해야 상태를 반영한다. 서로 다른 세부 행위를 임의로 선택하지 않는다.

불일치는 올바른 이해로 계산하지 않는다. 이때는 DB 전이 callback을 호출하지 않아 기존 `interpretation_pending`과 자동 연락 보류를 유지하며, writer에도 미확정 상태를 전달한다. 호출·구조 검증 실패와 의미 불일치를 분리한다. 원작 근거 읽기까지 성공한 뒤에만 확정된 전이를 반영한다.

- 기존 개발 16개: 사후 조합에서 올바른 일치 15개·불일치 보류 1개. 문제를 모두 이해했다는 16/16 결과가 아니다.
- 별도로 준비한 8개: 고정 계약 후 처음 생성한 양쪽 해석 모두 의미 8/8 통과. 식별자가 뜻을 암시하는 문제가 발견되어 동일 내용·기준을 유지한 UUID 대조를 추가했다.
- UUID 대조: 같은 8개에서 양쪽 모두 의미 8/8, 올바른 상태 변경 6/6, 잘못 허용한 변경 0건. 원래 8개에 더해 새 8개를 평가한 것으로 세지 않는다.
- 계약 SHA-256: `ca7d86eb232bff88f0792e57a6d4f58bb43b0612fdf3f1137b6c5e587334b90f`. UUID 입력 고정 SHA-256: `69d8dc46e31ecf48fef3cbc9e22536a483ee70530c35fdf8245d15300bcb532e`. 독립 의미 검토 SHA-256: `d72e07b720f39a6f853786d6639e281967c013f36f11f56aefbe75a86f81ff14`.
- 같은 모델의 오류는 서로 일치할 수도 있다. 이 방식은 독립 검증이나 보정된 신뢰도 점수가 아니며, 일반화 성능을 확정하지 않는다.

토큰 예산·스키마·생성 설정을 보존한 제품 입력 대조, 실제 DB를 사용하는 12개 다중턴 대화, 일정 정정·취소 연결 검사와 공개 재검증은 별도 완료 조건이다. 이 절은 아직 그 결과나 배포 완료를 주장하지 않는다. 이전 실패 출력·감사 기록은 모두 보존한다.
