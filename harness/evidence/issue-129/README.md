# Issue 129 — 사건 발신 근거 검증

## 발견한 오류와 변경

Issue 123의 실제 공개 Chromium 흐름은 초대·전화·후속 각 한 번과 휴식·재접속을 통과했지만, 사용자 답변 없이 후속 문자가 새 날짜를 확정해 말했다. 기능 성공을 내용 성공으로 처리하지 않고 사건 기능을 OFF로 되돌렸다. 일반 채팅은 유지했다.

`kiryu-daily-sms-v22`는 사건 초대와 통화 후속의 마지막 입력에 `episode-outbound-facts-v1`을 적용한다. 확인된 사실, 마지마의 미결 제안, 사용자의 동의를 구분하고 최신 정정·취소를 우선한다. 실제 원문의 메시지 ID와 화자만 근거로 표시하며, 날짜 의미나 동의를 코드로 추출하지 않는다. 원문이 없거나 반복 문구 때문에 출처가 모호하면 출처를 추정하지 않는다.

날짜 전체 금지, 특정 사용자 표현 분기, 출력 문구 치환은 추가하지 않았다. 초기 v21 발신 전용 수정 뒤 실제 연결 검사에서 reader가 일정 교체를 활동 전체 취소로 오인했다. `source-reader-v9`는 참여를 유지한 조건 변경인 `amend_participation`을 추가하고 기존 서버의 `accept` 전이로 검증한다. 최신 사용자 원문을 그대로 보존하며 참여 상태를 세부 조건에 대한 양측 합의나 행동 완료로 확대하지 않는다. UI·모델·생성 설정·DB 스키마는 바꾸지 않는다.

## 범위와 보존

- 기존 공개 실패: `references/local/gemma-chat/bowling-public/2026-10-30T21-43-35-480Z-chromium-fresh/`. 기능 summary와 별도 실패 content-review를 모두 보존한다. DB 감사에서 중복·범위 위반은 없었지만 잘못된 assistant 원문은 기록에 남아 있다.
- 초기 v21 직접 생성: `references/local/gemma-chat/bowling-grounding129/20261030T220356.474762Z/`. 실제 실패의 날짜 없는 초대·서버의 미확정 제안·빈 근거 ID를 미정 조건으로 사용했다. 조건과 seed는 생성 전에 고정했다. 독립 검토에서 18개 모두 좁은 사실 경계는 통과했으나 한국어 외 문자 혼합 1건과 후속 3문장 출력 9건을 별도 형식 실패로 남겼다.
- v21 연결 실패: `references/local/gemma-chat/bowling-grounding129-linked/20261030T220638.439975Z/`. 실제 reader·Gemma·격리 DB에서 초대·후속·사용자 네 턴을 실행했다. 세 번째 날짜 정정 턴에서 답장은 새 일정을 반영했으나 상태가 `closed/cancel`로 바뀌었다. 실행 오류 0건을 내용 성공으로 처리하지 않는다.
- 후속 5조건은 미정·인물 단독 제안·사용자 확정·정정 후 합의·취소다. 각각 seed 42·43·44를 적용하고 초대도 같은 세 seed로 검사했다. 모든 결과와 오류를 보존하며 재생성으로 실패를 대체하지 않는다.
- 종료 상태의 직접 생성은 방어적 builder 검사다. 운영에서 취소 후 새 발신을 접수했다는 의미가 아니다. 실제 접수·중단은 별도의 상태·경합 검사 범위다.
- 팬 판정과 실제 iPhone 검증은 미완료다. 공개 재검증과 최종 배포 결과는 연결 이슈에 실제 실행 후 기록한다.

## 결과 기록의 경계

고정 사례 기반의 개발 회귀 검사이며 미관측 상황의 오류 0건을 보장하지 않는다. 이전 `full-v4`의 12상황 중 10개 통과는 당시 소스의 평가로 유지한다. 이번 좁은 발신 검사와 분모를 합치거나 새로운 전체 성능 수치로 바꾸지 않는다.

v22의 고정 발신·연결·전체 12상황 검사를 새 경로에서 실행하고, 실제 결과와 소스·결과 해시를 현재 SHA의 PR/Issue 후속 기록에 연결한다. 이 문서는 아직 그 검사의 성공을 주장하지 않는다. 필수 CI가 통과하더라도 내용 검사와 독립 판정이 끝나기 전 자동 병합을 켜지 않는다. 비공개 원문·토큰·운영자 비밀값은 공개 증거에 포함하지 않는다.
