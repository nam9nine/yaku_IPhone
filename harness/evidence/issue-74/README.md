# 자동 연결 문자 UI 검증

2026-10-26, macOS arm64, Node 24.22.0, Playwright 1.64.1. 이 기록은 프런트엔드의 실행 결과이며 공개 API 배포와 실제 Gemma 답장 검증은 통합 단계에서 별도로 기록한다. 검증 SHA는 최종 커밋 이후 PR 증거에 넣는다.

## 수행한 검사

- `npm run check`: 타입·lint·포맷·348개 단위 테스트·production build·하네스 검사 통과.
- `tests/browser/live-ai-chat.spec.ts`, `day.spec.ts`, `story.spec.ts`: Chromium·WebKit 합계 66개 통과. 실제 모델을 호출하지 않는 고정 HTTP 응답을 사용했다.
- AI 연락처를 여는 기존 시각 검사 12개를 `--ignore-snapshots`로 실행해 고정 응답과 화면 로딩 대기를 확인했다. 이는 화면 전환 검증이며 스크린샷 회귀 통과가 아니다. 기준 이미지와 허용 오차는 변경하지 않았다.
- 360×800, 390×844, 430×932 반응형 검사와 낮아진 화면의 입력창·전송 버튼 검사를 포함한다. 360×430 캡처는 화면 높이 축소 조건이며 실제 iPhone 키보드 검증이 아니다.

자동 연결·익명 토큰 재사용·401 응답 시 한 번의 갱신·이전 토큰 이관·새로고침 후 기록 복원·cursor 이전 기록 조회·전송 UUID 재사용·IME·다중 줄·백그라운드 조회 간격·연결 실패 후 재시도를 확인했다. 보내지 않은 초안과 다른 연락처의 입력은 자동 전송하지 않았다. 서버 실패 출력을 정상 말풍선으로 보이지 않게 확인했다.

## 직접 확인한 화면

각 파일의 `chromium`과 `webkit` 이미지를 모두 열어 확인했다. 캡처는 production preview, `ko-KR`, `Asia/Seoul`, reduced motion, 동일한 이미지·글꼴 로딩 조건을 사용한다. 앱의 기존 고정 시계는 16:40이며 HTTP fixture의 대화 시각은 2026-10-26 09:00 KST다. “검증용 … 답장”은 화면 검사를 위한 명시적인 fixture이며 모델 품질 증거가 아니다.

| 파일                                     | 확인 내용                                                             |
| ---------------------------------------- | --------------------------------------------------------------------- |
| `haruka-390-{chromium,webkit}.png`       | 초기 스토리와 실제 서버 형식의 교환 구분, 저장 안내, 자유 입력창      |
| `majima-390-{chromium,webkit}.png`       | 마지마 대화 소유권과 답장 표시, 새 대화 뒤 오래된 카레 선택 버튼 없음 |
| `composer-360x430-{chromium,webkit}.png` | 두 줄 입력과 전송 버튼이 낮은 화면에서 겹치거나 가려지지 않음         |
| `unavailable-430-{chromium,webkit}.png`  | 이용 불가 안내·재시도·입력창 표시, 연결 주소·접속 키 입력 없음        |

레퍼런스 `idb-messages-ios27`의 로컬 원본 `references/local/real-device/ios27-messages-compose.jpg`와 이전 `native-thread-390.png` 기준을 함께 열어 비교했다. 출처는 [iDownloadBlog의 실제 조작 안내](https://www.idownloadblog.com/2026/06/12/send-handwritten-message-iphone/)이며 상세 출처·라이선스는 `references/real-device-sources.json`에 있다.

아바타와 이름 캡슐·뒤로 버튼·수신 회색 말풍선·꼬리·하단 캡슐 입력창의 기존 구조를 유지했다. 발신 초록색은 기존 프로젝트의 SMS 표현을 유지한 것이다. 저장 안내와 이용 불가 재시도는 이번 서비스에 필요한 표시이며 iOS 원본에 있는 요소라고 주장하지 않는다. 수평 잘림, 입력창과 버튼 겹침, 안내가 입력을 가리는 현상은 캡처에서 발견하지 못했다.

직접 확인 중 새 대화 뒤에도 초기 카레 선택 버튼이 남는 문제를 발견했다. 첫 서버 사용자 문자 이후에는 표시하지 않도록 수정하고 66개 브라우저 검사와 8개 캡처를 다시 수행했다.

## 남은 검증

- 실제 공개 Pages에서 고정 Worker를 통한 Gemma 대화·복원·장애 복구는 통합 검증 대상이다.
- 전체 브라우저 회귀, macOS·Linux 시각 기준의 변경 검토, 독립 리뷰와 배포 gate는 조정 에이전트가 수행한다.
- 실제 iPhone Safari와 실제 소프트 키보드에서는 아직 확인하지 않았다.
- 이 기록은 구현자의 직접 검토이며 독립 검토나 사용자의 인물 재현 팬 평가가 아니다.
