# 자동 연결 문자 UI 검증

2026-10-26, macOS arm64, Node 24.22.0, Playwright 1.64.1. 프런트엔드 고정 응답 검사와 실제 Gemma·공개 API 검사를 아래에서 구분한다. 검증 SHA는 최종 커밋 이후 PR 증거에 넣는다.

## 수행한 검사

- `npm run check`: 타입·lint·포맷·355개 단위 테스트·production build·하네스 검사 통과.
- `npm run test:e2e`: 최종 macOS Chromium·WebKit 전체 490개 통과. 실제 모델을 호출하지 않는 고정 HTTP 응답을 사용한다. 앞선 전체 실행의 시작 화면 한 건 실패 후, 동시 build가 없는 상태에서 전체를 다시 실행했다.
- `npm run test:visual`: 최종 macOS Chromium·WebKit 전체 224개 통과. 별도 독립 검토자가 각 운영체제의 expected·actual·diff를 직접 비교한 뒤 의도된 표제·저장 안내·입력창 변경에 해당하는 macOS 10개와 Linux 10개만 승인했다. Linux 후보는 CI run `40233505839`의 실제 출력이며 최종 Linux 회귀 통과 여부는 PR 검사에 남긴다. 허용 오차는 변경하지 않았다.
- Python 전체 272개와 Ruff 검사를 통과했다. 네트워크 복구 후 재전송과 세션 재사용 회귀를 추가해 AI 단위 검사 33개 및 대상 브라우저 검사 28개도 확인했다.
- 360×800, 390×844, 430×932 반응형 검사와 낮아진 화면의 입력창·전송 버튼 검사를 포함한다. 360×430 캡처는 화면 높이 축소 조건이며 실제 iPhone 키보드 검증이 아니다.

자동 연결·익명 토큰 재사용·401 응답 시 한 번의 갱신·이전 토큰 이관·새로고침 후 기록 복원·cursor 이전 기록 조회·전송 UUID 재사용·IME·다중 줄·백그라운드 조회 간격·연결 실패 후 재시도를 확인했다. 보내지 않은 초안과 다른 연락처의 입력은 자동 전송하지 않았다. 서버 실패 출력을 정상 말풍선으로 보이지 않게 확인했다.

직접 확인 중 새 대화 뒤에도 초기 카레 선택 버튼이 남는 문제를 발견했다. 첫 서버 사용자 문자 이후에는 표시하지 않도록 수정하고 66개 브라우저 검사와 8개 캡처를 다시 수행했다.

## 남은 검증

- 실제 공개 Pages에서 고정 Worker를 통한 Gemma 대화·복원·장애 복구는 통합 검증 대상이다.
- 로컬 전체 회귀와 기준 이미지 변경 검토를 마쳤다. 현재 커밋의 최종 독립 리뷰·Linux CI·배포 gate 결과는 PR 증거에서 확인한다.
- 실제 iPhone Safari와 실제 소프트 키보드에서는 아직 확인하지 않았다.
- 이 기록은 구현자의 직접 검토이며 독립 검토나 사용자의 인물 재현 팬 평가가 아니다.

## 실제 Gemma·DB·공개 API 통합 기록

`runtime-results.json`은 별도 실제 실행의 합성 진단 결과다. 방문자 원문과 인증값은 공개 증거에 넣지 않는다.

- 추가 학습 없이 고정 Gemma Q4_K_M, thinking OFF, 단일 생성 슬롯을 사용했다.
- 최종 v3의 20개×6턴, 두 30턴, 조건 쌍 8답장 합계 188개가 정상 종료했다. 정상 종료는 인물 품질 판정이 아니다.
- 사전에 선언한 준비된 모델·대기열 없는 첫 60요청(하루카)은 완료 p95 2.801초다. 두 인물의 짧은 대화 전체 120요청은 p95 2.906초, 실제 출력 9–66토큰이었다. 검색과 native 토큰 계산을 포함하고 모델 최초 로딩은 제외한다.
- 별도 SQLite와 실제 모델 하나의 2명·4명 동시 도착에서 FIFO를 확인했다. 4명 완료는 접수 후 약 2.00·3.81·5.31·7.17초였다. 작은 표본의 p95로 표현하지 않으며 ASGI 검사라 외부 네트워크 시간은 제외한다.
- 같은 Python 프로세스 안에서 API 앱을 재생성해 같은 토큰의 이력을 복원하고, UUID 재전송·최종 입력 재구성·방문자/인물 간 식별 문구 격리를 따로 검사했다. 이것은 전체 모델·Tunnel 프로세스 재시작 검증이 아니다. 원문 DB와 평가용 DB는 분리했다.
- 통합 실행기 전환 후 고정 공개 HTTPS 주소에서 두 인물의 실제 답장과 각 2개 이력 반환을 확인했다. Worker는 관리자·모델 포트를 전달하지 않는다. Pages 화면 자체 검증은 최종 배포 뒤 별도로 기록한다.
- 별도 실제 모델·API·관리자·named Tunnel 프로세스 재시작 후에도 같은 익명 토큰, 완료 작업 두 건, 원문 이력 두 묶음이 정확히 유지됐고 UUID 재전송은 새 생성을 만들지 않았다. 최초 즉시 재시작은 TCP TIME_WAIT를 사용 중 포트로 오인해 실패했다. 포트 탐침을 수정한 뒤 실제 복원을 확인했고, 독립 검토자가 임시 포트 10회에서 기존 실패·수정 성공·실행 중 리스너 차단을 재현했다.

독립 검토자는 최종 188개를 모두 읽었다. 정정된 장기 메뉴 4/4와 확인 문구 2/2는 반영됐으나, 두 조건을 모두 적절히 처리한 문맥 쌍은 2/4였다. 근거 없는 원작 사실 창작, 보고 없음과 미발견/미구매의 혼동, 취소 상태 누락과 불필요한 면박이 남았다. 여섯 축을 분리 기록하며 평균 하나나 팬 승인으로 바꾸지 않는다. 최초 v1 실패와 수정 후 출력은 모두 별도 보존했다.

시스템 swap은 실행 전 `6972.75M`, 실행 후 `8299.69M` (`sysctl vm.swapusage` 원문 단위)였다. 다른 앱·브라우저·검사를 함께 실행한 시스템 전체 관측이다. 빠른 응답을 확인했어도 메모리 여유나 다수 방문자 용량을 보장하는 자료는 아니다.
