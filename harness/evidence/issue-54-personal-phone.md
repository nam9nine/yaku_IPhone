# Issue 54 검증 기록

## 구현과 화면

- 힌트 없는 `1225` 암호. 일반 잠금 해제와 잠금 알림·위젯 목적지 모두 암호를 거친다.
- 선택한 사진 6장과 기존 배경·즐겨찾기 ID 호환. 홈 위젯은 가족 사진/마메 사진으로 연결된다.
- 마지마 전용 로컬 AAC 32초 파일. 수신 중 재생, 응답·거절·만료·초기화·숨김·무음에서 중지한다.
- 수신은 `16:40 → 마지마형님`, 연결 후에는 `00:00 → 마지마형님` 순서다.

macOS arm64, Node 24.22.0, Playwright 1.64.1의 Chromium·WebKit에서 360×800, 390×844, 430×932를 캡처했다. `issue-54/`의 암호·홈·사진·수신·통화 30장과 `capture-results.json`에 실행 결과를 보관했다. 캡처 중 pageerror는 0개다.

직접 검토에서 최초 암호 화면 뒤로 시계·알림이 겹친 문제를 발견해 잠금 내용 숨김과 배경 블러를 적용한 뒤 재캡처했다. 숫자판과 취소·지우기, 사진 6장, 시간 아래 이름 및 전화 버튼은 잘림 없이 표시된다. WebKit은 첫 버튼에 접근성 포커스 테두리가 보인다.

Apple User Guide의 잠금 화면(`apple-lock-screen-image`)과 사진 보관함(`apple-photo-library`)을 직접 열어 상태바·사진 그리드·하단 조작의 구조를 비교했다. 사진은 사용자 선택 6장으로 줄었으며 앱 구조를 재설계하지 않았다. 수신 이름 순서와 힌트 없는 네 자리 암호는 사용자 지시를 적용했다. 실제 iPhone의 픽셀 일치나 보안 잠금을 검증한 것은 아니다.

## 실행한 로컬 검사

- `npm run check`: 타입·lint·format·318개 단위 검사·빌드·하네스 통과.
- `npm run test:e2e -- --workers=4`: Chromium/WebKit 454개 통과. 실제 로컬 미디어의 재생/응답 정지, 알림 센터 위 암호 모달 포커스, 오답/취소/재잠금, 작은 높이, 사진/배경 저장을 포함한다.
- `npm run test:visual -- --update-snapshots --workers=4`: 의도된 macOS 후보 이미지 생성 186개. 생성 자체와 승인은 구분한다.
- `npm run test:visual -- --workers=4`: 기준을 자동 변경하지 않는 회귀 검사 186개 통과.

최초 동작 검사에서 이전 사진 이름/26장 기대값 8건을 새 콘텐츠에 맞게 수정했다. WebKit 재잠금 후 포커스 실패 1건은 암호 모달의 뒤 화면 숨김 적용 뒤 대상 검사와 전체 검사에서 재확인했다. 상태바 추가 후 단위가 모호해진 암호 이미지 locator도 입력 점으로 한정해 재검사했다. 실패를 검증 통과로 기록하지 않았다.

## 기준 이미지 변경 이유와 검토

홈 위젯 사진, 보관함 6장, 사진 상세, 수신 이름/시간, 최근 앱 뒤의 홈 사진, 새 암호 숫자판이 변경 대상이다. PC 하루카 장면에는 암호를 키보드로 입력한 뒤 프로필 버튼의 포커스 테두리가 추가되며 기존 메시지 내용/배치는 유지된다. 허용 오차·mask는 변경하지 않았다. macOS/Linux 후보와 독립 검토 판정은 최종 PR의 현재 SHA 증거에 연결한다.

`requirements_audit`는 구현 코드와 30장 전체 캡처를 독립 검토했고 수정이 필요한 결함을 찾지 못했다. 기준 이미지 변경의 별도 검토와 최종 SHA 판정은 PR 증거에 기록한다.

## 제한

실제 iPhone Safari는 미검증이다. WebKit 검사와 실제 기기의 자동 재생·음량 정책은 동일하다고 주장하지 않는다. 기존 15초 무응답 만료를 유지한다. 암호는 체험용이며 서버 접근 제어가 아니다. AI 대화·반복 수신·텍스트 통화·추가 앱은 이번 Issue 범위가 아니다. 배포 완료와 공개 확인은 실제 Actions 결과 이후 Issue/PR에 기록한다.
