# Issue 122 — 볼링 원작 근거와 AI 사건 판단 검증

[Issue #122](https://github.com/nam9nine/yaku_IPhone/issues/122)의 모델 입력·원작 근거·사건 해석 증거다. 2026-10-31 KST에 완료한 `full-v4`는 실제 Gemma 출력 62건 모두 정상 생성했고, 독립 에이전트가 고정 12개 상황 중 10개를 적절하다고 판정했다. 사전에 정한 10/12 기준과 관찰된 원작·방문자 경험 혼동 0건, 현재 취소 무시 0건을 충족했다. **두 상황의 판단 실패와 말투 문제는 남아 있으며 팬 검토는 미완료다.**

## 변경 범위

- 원작 볼링 사건·마지마의 승부 목적을 승인된 사건 전용 근거로 연결했다. 초대 전 일반 대화에는 볼링 사건을 주입하지 않는다.
- 실제 사용자·답장과 assistant-only 초대·통화 후속을 메시지 ID·순서·통화 결과를 가진 타임라인으로 제공한다. 사용자 발언을 만들어 대화 쌍을 채우지 않는다.
- reader는 현재 메시지 ID·사건 버전을 검사한 행위 해석을 반환한다. 논의 재개, 참여 수락, 진행 보고, 최종 결과 보고를 구분한 뒤 기존 DB 전이로 변환하며 원래 해석과 검증 결과를 함께 기록한다.
- writer에는 갱신될 사건 상태와 이번 답장의 과제를 전달한다. 초대 발신 목적을 매 답장의 목적으로 반복하지 않는다. 원작 근거·참고 장면은 현재 방문자의 행동 완료 사실과 분리한다.
- reader가 실제 제공된 `(자료 ID, 필드)` 쌍만 선택하도록 응답 스키마를 제한한다. 정확히 같은 선택의 중복은 감사 기록을 남기고 정규화하지만 없는 필드·다른 방문자·오래된 상태 근거를 임의로 고치지 않는다.
- 토큰 예산을 넘으면 중복 표현·불필요한 과거 문맥부터 줄인다. 최후 수단으로 과거 원문 전체를 명시적으로 생략하고 메시지 ID를 남긴다. 본문의 일부를 잘라 약속을 바꾸지 않으며 현재 사용자 입력과 DB 원문은 보존한다.

`ai/chat/registry.json`의 `majima-bowling-challenge`, `majima-retrain-rival`에 URL·확인일·원문 해시·발췌 위치·검토 근거·사용 범위를 기록했다. 두 자료는 `episode_only=majima-bowling-v1`이다. 원작 발신자는 니시다이며, 마지마가 직접 문자를 보내는 부분은 `ai/chat/episodes.json`에 **일상 IF 각색**으로 명시했다. 한국어 생성 문구를 원작 정식 대사로 표시하지 않는다.

이 구조는 [RoleLLM](https://aclanthology.org/2024.findings-acl.878/)의 역할·지식·표현 구분과 [Generative Agents](https://arxiv.org/abs/2304.03442)의 기억 기반 행동 계획을 참고한 제품 설계다. 논문의 성능을 이번 구현의 성능으로 사용하지 않는다.

## 최종 독립 내용 검토

구현에 참여하지 않은 `/root/episode_independent_review`가 실제 writer 출력·사건 상태·근거를 함께 확인했다. reader 초안의 답안을 사용자에게 전달된 답장으로 대신 평가하지 않았다.

| 상황                                                        | 판정                        |
| ----------------------------------------------------------- | --------------------------- |
| `pronoun_accept` — 실제 초대와 “그거” 연결                  | 통과                        |
| `accept_cancel` — 수락 뒤 취소와 기억                       | 통과                        |
| `defer_resume` — 보류 후 논의·참여 구분                     | **실패**                    |
| `injury` — 부상 사정 유지                                   | 통과                        |
| `topic_change` — 다른 화제와 사건 보류                      | 통과                        |
| `decline` — 거절 존중                                       | 통과                        |
| `reported_result` — 도착·경기 완료·사용자 승리 보고 구분    | 통과                        |
| `ambiguous` — 미결정·생각 중 보류                           | 통과                        |
| `canon_boundary` — 원작 니시다 발신과 이번 마지마 발신 구분 | 통과                        |
| `notice_recall` — 선제 연락 회상과 활동 대상 구분           | **실패**                    |
| `missed_followup` — 부재중 후속과 다음 대화                 | 통과, 일부 표현·문맥 아쉬움 |
| `idle_followup` — 연결 후 무응답 종료와 다음 대화           | 통과                        |

남은 실패는 구체적으로 다음과 같다.

- `defer_resume` 4턴: 참여에는 긍정하고 시간만 미정인 답을 `discuss_proposal`로 읽어 `deferred`를 유지했다. 표면 답장은 수락처럼 응답해 상태와 불일치했다. 논의 허락을 곧바로 참여 수락으로 만들던 3턴 문제는 해결됐지만 전체 상황은 실패다.
- `notice_recall` 2턴: 싸움을 원하지 않는다는 답을 볼링 거절로 읽어 `closed/decline`로 처리했다. 다음 턴에 주먹 승부가 아닌 볼링임을 설명했지만 미결정 상태로 회복하지 못했다.
- 말투는 5개 상황 적절·7개 상황 일부 아쉬움이다. 반복 반응, 어색한 사투리·조사, 주어가 생략된 통화 표현이 남았다. 팬 승인 또는 완전한 마지마 재현으로 표시하지 않는다.

원작·방문자 경험 혼동 0건과 현재 취소 무시 0건은 **이 고정 표본의 실제 답장 관찰**에 한정한다. 모든 자유 대화의 무오류나 실제 행동 확인을 보장하지 않는다.

## 자동 검사와 입력 예산 검증

- `PYTHONPATH=ai <ci-venv>/bin/python -m unittest ai.tests.test_episode_prompt ai.tests.test_chat_reader ai.tests.test_chat_prompt`: 최종 AI 수정에서 76개 통과. 변경 Python 파일 Ruff 검사·포맷 검사와 `git diff --check` 통과.
- 전체 Python 회귀의 이전 실행은 437개 중 1개 실패·3개 skip이었다. 실패는 기존 OCR worker의 이미지별 시간 제한 관련 검사였으며 해당 수정·최종 전체 회귀는 조정 에이전트가 별도 이슈에서 처리한다. 이 문서에서 전체 검사 통과로 바꾸지 않는다.
- 실제 Gemma 네이티브 토큰 계산으로 1,000자/2,644바이트의 고밀도 합성 입력을 검사했다. 현재 입력 자체가 너무 크면 `InputBudgetError`가 날 수 있지만, 저장된 긴 과거 메시지 뒤 짧은 입력은 writer 2,243~2,278토큰·reader 2,704~3,906토큰으로 회복했다. 문맥 크기나 생성 예산을 늘려 통과시키지 않았다.
- 예산 회귀는 모델 생성을 하지 않은 토큰·구조 검사다. fallback 시 과거 내용을 추정하지 않도록 생략 표시와 근거 ID를 남기며 reader 초안이 생략 내용을 writer로 우회 전달하지 않는지 검사했다. 현재 입력이 너무 커 실패하기 전에 검증된 사건 전이는 적용될 수 있다는 제한도 남는다.
- `full-v4` 평가 실행기의 접수부터 완료 확인까지 측정값은 초대 12건 20.435~25.159초, 사용자 답장 48건 29.621~68.376초, 빠른 후속 2건 3.886~3.891초였다. 단일 모델 순차 평가이며 동시 사용자 성능·공개 전달 지연·p95 서비스 목표의 검증으로 사용하지 않는다.

## 로컬 원본 증거와 완료 경계

다음 경로는 저장소 루트 기준의 ignored 로컬 증거다. 실제 방문자 대화를 평가에 사용하지 않았으며 토큰·키·운영 DB를 공개 증거에 복사하지 않는다.

- `references/local/gemma-chat/bowling-eval/{full-v1,corrections-v2,full-v3,full-v4}/`: 실행 manifest, 입력·출력과 상태를 포함한 `responses.jsonl`, summary 또는 중단 사유. 원래 실패 결과 보존.
- `.tooling/majima-episode/full-v3-independent-review.json`, `full-v4-independent-review.json`: 독립 상황별 판정, 말투 평가, 구체적 실패 근거.
- `.tooling/worktrees/episode-ai/.tooling/high-density-reader-v8.json`: 고밀도 입력과 다음 짧은 턴의 예산 검사.
- `.tooling/worktrees/episode-ai/.tooling/reader-v8-replay-errors.json`: 기존 실패 raw 결과의 재파싱과 없는 필드 거절 검사.
