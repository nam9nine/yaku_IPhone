# Issue 33 — 실사용 앱 화면·상태바·수신 연출

## 구현과 직접 관찰

전화의 최근 통화/부재중 필터, 검색, 연락처, 즐겨찾기, 키패드, 음성 사서함을 다섯 하단 탭으로 구성했다. 홈에 연락처 앱을 별도로 배치했으며 두 진입점의 연락처 추가 결과를 공유한다. 설정의 키류 프로필과 계정 상세, 메시지의 목록/하단 검색/회색·초록 버블, 시간·통신 신호·Wi-Fi·배터리 상태바를 추가했다. 사용자 첨부 실사용 캡처의 구성을 비교 기준으로 삼았다.

상단 드래그는 safe area 아래 40–112px에서 시작한다. 패널은 이동 중 손가락을 추적하고 취소하면 원위치로 돌아간다. 장보기 완료 후 마지마의 전화가 한 번 수신되며 응답/거절/15초 무응답을 구분한다. 수신 중 재접속은 부재중으로 복원한다. 배지·알림·최근 통화는 같은 이벤트 상태를 읽는다. 실제 통화·오디오·기기 권한은 사용하지 않는다.

갤러리의 26장은 로컬에 저장한 공식 게임 원본이다. 출처·해시·권리 상태는 `references/kiryu-gallery.json`, 창작 설명은 `src/day/gamePhotos.json`에 분리했다. 기존 임의 생활 사진은 갤러리에서 제거하고 ignored 참고 보관소로 옮겼다. 아이들의 창작 그림은 선택 배경으로 남아 있다.

## 로컬 실행 결과

- 환경: macOS arm64, Node.js 24.22.0, Playwright 1.64.1, production build.
- `npm run check`: 타입·lint·포맷·단위 224개·빌드·harness 통과.
- `npm run test:e2e`: Chromium/WebKit 전체 350개 통과. 세 모바일 크기, 작은 높이, 확대 글자, 상태 보존, 입력 취소와 키보드 대체 조작을 포함한다.
- `npm run test:visual`: 기준 덮어쓰기 없이 Darwin 168개 통과. 시각 기준 생성 실행과 일반 비교 실행을 구분했다.
- 홈 복귀 후 알림 센터 진입 경합: 양 엔진 각 10회, 총 20회 반복 통과. 지연 RAF 복원을 같은 DOM 커밋의 layout effect로 변경했다.
- 별도 양 엔진 실제 조작: 상태바의 가상 네트워크 반영, 하루카→카레→수신→거절→부재중 기록, 전화 5탭, 프로필, 26장 이미지 로딩, 상단 드래그와 재접속을 확인했다. 페이지 오류와 로컬 자산 오류는 0건이었다.

## 직접 이미지 검토와 독립 검토

`harness/evidence/issue-33/`에 다크 화면 11장(390×844)을 보관한다. 전화·키패드·설정·수신 배너는 360×800, 430×932도 확인했다. 기존 라이트 화면·짧은 화면·PC 프레임은 별도 기준에서 유지했다. 첨부 캡처와 비교해 상태바 여백, 원형 조작, 들여쓴 구분선, 프로필 크기, 발신 초록색을 조정했다.

구현에 참여하지 않은 `/root/asagao_review`가 코드와 Darwin 전/후 168장을 직접 확인했다. 취소 후 다음 탭 차단, 수신 화면의 키보드 포커스 충돌, 부재중 알림의 이전 키패드 진입, 작은 높이의 키패드/통화 종료 접근 문제를 지적했고 수정 후 두 엔진에서 재확인했다. 홈 복귀 포커스 수정도 별도로 실행 검토했다. 해당 범위에서 남은 P1/P2가 없으며 Darwin 기준 교체를 승인했다.

Linux Ubuntu 24.04 seed run `40035728815`에서 동작 350개가 통과했다. 시각 168개는 기존 기준과의 차이 또는 신규 기준 부재로 실패했으며 artifact의 실제 PNG 168장을 추출했다. macOS 이미지를 복사하지 않았다. 새 기준 등록 뒤의 일반 비교는 최종 CI에서 확인한다.

Linux 기준과 최종 SHA의 리뷰/필수 검사 결과는 현재 PR의 `harness-evidence` 및 GitHub Actions를 원본으로 기록한다. 이 파일 안에 자기 커밋 SHA를 넣지 않는다.
