## 대상과 환경

- 기능 소스: `a23e83d1793f48760ebcde233017f893e48e1369`. 캡처 빌드: `index-Bm_xuPCn.js` / `index-CRvafDq5.css`. 최종 증거 SHA는 PR 본문에 기록한다.
- macOS arm64, Node 24.22.0, Playwright 1.64.1, Chromium·WebKit. Linux는 Ubuntu 24.04 CI에서 별도 기준을 사용한다.
- 고정 시각 2026-10-24 09:41, ko-KR, Asia/Seoul, 기본 배경·라이트 모드. 기존 시스템 회귀 장면은 해당 테스트의 2026-10-23 시각을 유지한다.
- 반응형 크기 360×800, 390×844, 430×932. 추가 짧은 화면 360×430 및 큰 글자 130%를 확인했다. 실제 기기 모델의 실측값이라는 의미는 아니다.

- 화면 비교는 기존 110개 중 74개 유지, 연락처·대화·메모 목록/상세·사진 목록 30개와 최근 앱 6개를 변경 대상으로 확인했다. macOS 변경 36장을 원본과 직접 비교하고 독립 승인 후 등록했다. 일반 `npm run test:visual` 재실행 110개 통과. `.tooling/motion26-visual-final.log`.

## 직접 확인한 화면과 모션

[캡처 폴더](issue-26/)에 두 엔진의 긴 드래그·느린 최근 앱·빠른 홈 복귀 시트와 네 앱의 정적 시트를 보관한다. `motion-observations.json`에는 실행 브라우저·자산 버전·실제 카드 크기·오류 여부를 기록했다.

- 하단에서 120→300→500→650px 올리는 동안 실제 앱 너비가 390→320.69→216.72→101.20→46.80px로 감소했다. 마지막 release는 홈이었다.
- 중간 드래그에서 실제 이전 앱이 왼쪽에 보이고, 손을 놓으면 현재 크기에서 최근 앱으로 정착한다. 카드 선택은 해당 카드 위치에서 앱을 연다.
- 홈으로 끝까지 올릴 때 이전 카드와 배경 흐림이 사라진다. WebKit의 중첩 backdrop-filter 문제를 실제 홈 레이어의 흐림 처리로 해결하고 양 엔진 캡처에서 확인했다.
- 빠른 상승, 천천히 연속 상승, 멈춤, 짧은 취소, pointercancel, resize, 반복 입력, reduced motion을 검사했다. 400ms 누르고 기다린 뒤 빠르게 올려도 홈으로 돌아간다.
- 최근 앱 복제에서 실제 입력값·읽던 스크롤·제목 정렬을 보존한다. 버튼의 기본 가운데 정렬을 상속하던 문제를 수정했다.
- 뒤로 가기 정착 중 실제 하단 홈 제스처를 시작하면 지연된 탐색을 취소한다. Wi-Fi 화면에서 이 동작 후 설정을 다시 열어 Wi-Fi 화면 유지를 두 엔진에서 확인했다.
- 메모 검색은 하단에 배치하고 오늘·어제·이전 7일·이전 30일·월/연도로 묶는다. 서울 자정과 7/8일·30/31일·연도 경계의 9개 fixture를 양 엔진에서 확인했다.

## 비교 자료와 판정 범위

[원문 색인](../../references/real-device-sources.json)과 [모션 설계](../../docs/fluid-motion.md)에 출처·버전·저자·로컬 경로·한계를 구분했다. MacMost의 실제 조작 영상 00:52–00:56과 01:16–01:20, iDownloadBlog의 메시지·사진 사용 캡처, Tom's Guide의 메모 목록, MacRumors의 연락처 화면을 직접 열어 비교했다. 구형/베타 자료를 iOS 27 정식 화면으로 바꾸어 기록하지 않았다.

독립 검토자 `agent:/root/motion_audit`는 구현에 참여하지 않았다. held flick 판정, 제목 정렬, 실제 홈 제스처의 뒤로 이동 취소, 메모 기간 그룹의 지적을 수정 후 재검증했다. 기능 소스 검토에서는 미해결 확정 문제가 없다고 보고했다. macOS와 Linux 각각 36개 변경 이미지를 이전 기준과 직접 비교해 독립 승인했다. 각 플랫폼 74개 기존 장면은 유지한다. 최종 SHA 승인은 PR 증거에 별도로 연결한다.

실제 iPhone Safari·ProMotion·소프트 키보드는 미검증이다. 캡처 중 측정한 rAF 간격은 스크린샷 부하가 있으므로 기기 성능 수치로 사용하지 않는다. 왼쪽 뒤로 가기는 현재 화면을 이동하고 실제 목적 화면으로 전환하지만 드래그 아래에 이전 화면을 실시간으로 겹쳐 그리지는 않는다. 전체 iPhone UI·기능과 완전히 동일하다고 판정하지 않는다.
