# Issue 83: 질문의 핵심과 인물 관계를 반영하는 대화

## 문제와 범위

실사용 로그의 재질문 회피, 감정 고착, 주체 혼동과 관계 오류를 합성 문항으로 재현한다. 위치 질문만을 감지하거나 정해진 답장을 반환하지 않고 현재 의도, 앞선 응답의 충족 여부, 정보의 근거와 인물의 선택을 구분하도록 입력을 개선한다. 반복 요청이 정당한 거절을 무조건 뒤집게 하지 않는다.

사용자가 승인한 새 대화의 IF 초기 위치는 하루카=나팔꽃, 마지마=카무로쵸다. 이후 명시한 이동과 정정이 우선한다. 원작 관계와 IF 현재 상태를 구분한다. 공식 출처로 확인한 핵심 관계를 검색 순위와 관계없이 입력에 제공하되 인물별 허용 범위와 출처 검증을 유지한다.

## 순서와 검증

1. 기존 대화 분석은 로컬에서만 수행하고 공개 fixture에는 합성 대화만 사용한다.
2. 개발 문항 30개(기본 18개·일반 상황 12개)와 구현 담당자가 읽지 않은 독립 문항 28개의 기존 출력을 기록한다.
3. 인물 카드·원작 근거·입력 조립과 관련 테스트를 수정한다. 상태 그래프나 추가 모델 호출은 필요가 확인되기 전에는 만들지 않는다.
4. 개발 문항으로 실제 Gemma 출력과 토큰 예산·원문 재구성·격리를 검사한다. 독립 문항은 수정안을 고정한 뒤 별도로 평가한다.
5. 코드·출처 독립 리뷰, 현재 SHA의 검사와 PR gate, 병합 후 로컬 API 재시작과 공개 API의 버전을 확인한다.

품질 평가는 말투, 판단, 관계, 지식, 문맥, 형식을 나눠 기록한다. 에이전트 평가는 팬 승인이 아니다. 속도보다 품질을 우선한다는 후속 요청에 따라 Thinking·생성 예산도 이 품질 변경에 포함한다. `ai/THINKING.md`의 native 계약과 실제 답변으로 검사한다. 답장 도착의 랜덤 지연과 알림은 별도 Issue 84에서 구현한다.
