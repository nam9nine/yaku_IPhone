# Issue #43: 원문 전체 수집과 인물 보존 전처리

## 목적과 범위

MNBVC의 고정된 Yakuza 디렉터리에 있는 8개 파일을 모두 수집하고 전수 정제한다. 이 범위는 MNBVC 전체나 용과 같이 전 작품의 완전한 대본을 뜻하지 않는다. 원문과 결과는 `references/local/yakuza-corpus/`에만 보관한다.

사용자 추가 요청에 따라 키류와 기존 다섯 명의 대화만 필터링하지 않는다. 다테·아키야마·니시키를 포함한 우선 검토 별칭은 언급 색인에 사용하며 명단 밖의 모든 인물과 언어도 보존한다. 화자·청자·관계는 이름 검색으로 확정하지 않는다.

## 구현 순서

1. pinned manifest와 원본 크기/SHA-256을 기록하고 다운로드·캐시 검증을 구현한다.
2. 원본 언어·메타데이터와 출처를 보존하는 정규화 함수와 합성 fixture 검사를 만든다.
3. 전체 파일을 스트림 처리하고 장면 후보·이름 후보·언급·대화 후보·보류 색인을 만든다.
4. 행수 수지, 무결성, 보수적 정제, 같은 입력 재실행 결과를 검사한다.
5. 실제 데이터 표본과 최종 diff를 독립 검토하고 PR gate·병합·배포를 확인한다.

## 검증과 불확실성

- upstream 중복은 중국어 기준이며 저품질 개수는 중국어/영어 누락 통계다. 한국어 필터로 사용하지 않는다.
- source key의 테이블 위치와 JSONL 행 번호는 검증된 대화 순서가 아니다.
- 게임 빌드·정식 한국어 번역과의 일치·화자/청자는 이번 자동 처리만으로 검증할 수 없다.
- 알려진 제어 코드만 제거하며 미해결 변수·미확인 태그·언어 의심은 보류한다.
- 모든 정제 행은 `trainingEligible: false`이며 SFT 메시지/합성 대사/학습은 이번 범위 밖이다.
- 원문은 공개 저장소·앱 빌드·CI artifact에 넣지 않는다. 테스트에는 새로 작성한 합성 텍스트만 사용한다.
- `npm run check`, 다운로드/파싱 실패·행 보존·재현성 테스트, 실제 8개 파일 실행 결과를 기록한다. 앱 UI 변경이 없어 직접 시각 비교는 미적용이며 CI의 브라우저 실행 정책은 유지한다.

실행 결과와 남은 제한은 별도의 증거 문서와 Issue에 기록한다.
