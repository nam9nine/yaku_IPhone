# Issue #123: 볼링 문자·전화 통합과 공개 전달

## 목적

기존 iPhone UI에서 서버가 관리하는 초대·수신 전화·후속 문자를 실행한다. 방문자 입력을 막지 않고 다른 인물에게도 바로 문자를 보낼 수 있게 한다.

## 구현 순서

1. 공개 health의 기능 지원을 확인하고 인증 세션과 기존 이력을 복원한다.
2. 10초 활성 보고와 잠금·숨김·통화·답장 대기의 즉시 보고를 연결한다.
3. 사건 작업 ID로 조회·타이핑·전달 확인을 구분한다. 늦은 결과가 새 요청을 지우지 않게 한다.
4. 서버의 통화 claim을 확인한 뒤 수신 화면을 열고 종료 결과를 한 경로로 보고한다.
5. 사건 기능 ON에서 기존 마지마 자동 문자·전화만 대체한다.
6. Worker에 인증된 사건 경로와 정확한 capability query만 추가한다.

## 검증과 반영

- 두 탭·재접속·claim 응답 유실·사용자 입력 경합·무응답 흐름을 Chromium과 WebKit에서 검사한다.
- 실제 캡처로 입력창, 타이핑, 하단 이동, 알림 중복을 확인한다.
- DB 백업 후 Mac API는 우선 기능 OFF로 반영하고 Worker와 Pages를 배포한다.
- 신규 공개 클라이언트 지원을 확인한 뒤 `KIRYU_EPISODES_ENABLED=1`로 API를 실행한다.
- 기존 주소의 새 세션과 기존 세션에서 실제 Gemma와 활성 시간 흐름을 확인한다.
- 문제 발생 시 플래그를 끄고 일반 채팅을 유지한다. 실기기와 팬 검토는 관찰 결과가 있을 때만 완료로 기록한다.

실행 결과는 PR 증거에 기록한다. 이 문서는 예정된 절차이며 완료를 뜻하지 않는다.
