# Issue 54 — 개인 사진, 암호 잠금, 마지마 벨소리

## 목표와 범위

힌트 없는 암호 `1225`, 사용자 첨부 6장, 마지마 전용 첫 32초 벨소리, 시간 바로 아래 `마지마형님` 이름을 기존 앱에 연결한다. 기존 캐릭터·장보기·탐색·영구 저장은 유지한다. AI 연결과 다른 신규 앱, 반복 수신은 이번 배포와 분리한다.

## 구현 순서

1. 최신 main 기반 Issue·브랜치 준비, 자료를 public과 출처 색인으로 옮긴다.
2. 암호 입력 컴포넌트와 앱 목적지 보존을 연결한다. 스와이프·알림·위젯·키보드로 우회되지 않게 한다.
3. 갤러리 6장과 기존 배경/즐겨찾기 ID 호환을 구현한다.
4. 수신 오디오 수명주기, 무음·볼륨, 재생 제한 처리와 이름 배치를 구현한다.
5. 브라우저 테스트를 실제 암호 입력 흐름으로 갱신하고 회귀·새 경계 사례를 확인한다.
6. macOS/Linux의 의도된 화면 변경을 각각 캡처·직접 비교하고 독립 리뷰를 받는다.
7. 현재 SHA의 필수 gate 통과 후 squash 병합, Pages 배포와 공개 URL을 확인한다.

## 검증

- 오답/지우기/취소/재잠금/새로고침과 올바른 암호, 잠금 알림·위젯 목적지 보존.
- 새 사진 6장 로딩·확대·위젯·배경 설정·저장 복원, 과거 배경 ID 호환.
- 벨소리 수신 재생·응답/거절/만료/초기화 중지·중복 방지·무음/볼륨·재생 거부 후 복구.
- Chromium/WebKit, 360×800·390×844·430×932와 작은 높이/키보드/reduced motion.
- `npm run check`, `npm run test:e2e`, `npm run test:visual`, 실제 이미지 검토.

## 제한

체험용 암호는 서버 인증이 아니다. 실제 iPhone Safari의 자동 재생 정책과 물리 기기 터치는 별도 미검증으로 기록한다. 사용자 제공 이미지와 지정 음원의 출처·허가 미확인 상태를 보존하며 화면에 설명 패널을 추가하지 않는다. 실행 결과는 이후 evidence에 기록한다.
