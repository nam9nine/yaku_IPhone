# Issue 60 — 생활 앱과 연락처·캘린더 시각 기준

대상: [Issue 60](https://github.com/nam9nine/yaku_IPhone/issues/60). 기준 코드는 `dcd21cb`이며 Issue 58/PR 59에서 이미 배포한 UI를 회귀 검사에 반영한다. 화면 배치·스타일·허용 오차는 유지한다. 전체 검사에서 발견한 검색 결과의 키보드 접근성 결함은 조정 에이전트가 허용한 추가 범위로 수정한다.

## 계획

- 기존 macOS Chromium/WebKit 시각 검사를 먼저 실행하여 변경 장면과 diff를 확보한다.
- 홈의 생활 앱 아이콘, 관계·메모를 제거한 연락처 목록/상세, 연도를 제거한 고정 10월 캘린더만 이전 기준과 비교하여 갱신한다.
- 음악 보관함/곡 상세, 택시 목적지/경로, 카레 재료/조리 단계의 360×800·390×844·430×932 대표 장면을 추가한다. 짧은 390×400 화면의 조리 단계도 확인한다.
- production preview는 다른 작업과 겹치지 않는 4175 포트를 사용한다. locale `ko-KR`, timezone `Asia/Seoul`, 고정 시간, reduced motion과 명시적인 색상 조건을 유지한다.
- 이전 기준·새 캡처·diff를 직접 열고 실제 관찰을 남긴다. Issue 58의 추적 캡처와 사용자 요구를 주 비교 근거로 사용하며, `apple-home-screen-image`·`idb-contacts-ios26`는 화면 구조의 보조 자료로만 사용한다.
- 기준 수용 뒤 `check`, 전체 `test:e2e`, 전체 `test:visual`을 실행한다. Linux 캡처와 최종 독립 검토는 조정 에이전트가 별도로 진행한다.

## macOS 실행 관찰

- 환경: macOS 26.5.2 arm64, Node 24.22.0, Playwright 1.64.1, Chromium/WebKit. 다른 작업과 분리한 4175 production preview를 사용했다.
- 기존 기준과 첫 비교: 186개 중 154개 통과, 의도한 기존 화면 변경 32개 확인. 홈 6장·작은 홈 2장·검색 2장·연락처 상세 12장·캘린더 6장·최근 앱 4장이다. 연락처 목록과 나머지 기존 화면은 기준 변경 없이 통과했다.
- 홈·검색은 새 앱 아이콘과 검색 순서만 바뀌었다. 연락처 상세는 관계·메모 카드가 제거되고 사진·이름·메시지 버튼은 유지됐다. 캘린더는 제목의 연도를 제거하고 10월 24일·17:00 장보기 일정을 유지했다.
- 최근 앱 4장은 새 홈 아이콘이 카드 바깥 배경의 흐림에 반영된 차이다. Safari/설정 카드의 내용·크기는 유지되며, 두 번째 캡처도 첫 캡처와 픽셀이 완전히 같았다. 기존/새 이미지와 diff를 직접 열고 갱신했다.
- 신규 생활 앱 38장을 생성하고 모두 직접 검토했다. 보관함 3곡·곡 상세의 감상 링크, 목적지 목록·경로 카드, 카레 재료·장보기 연결·2단계 조리 버튼이 보인다. 390×400에서도 단계 설명과 이전/다음 버튼이 잘리지 않는다. 360 너비의 조리 설명 줄바꿈은 기존 UI 그대로다.
- `npm run check`: 단위 테스트 318개를 포함해 통과. 전체 macOS 시각 검사: 224개 통과. 실행은 npm wrapper와 ignored 임시 포트 설정으로 수행했다.
- 첫 전체 브라우저 검사는 458개 통과·4개 실패였다. 짧은 화면의 기존 가로 검색 목록에 새 앱이 앞에 추가되면서 Safari가 처음부터 보여야 한다는 검사의 가정이 맞지 않게 됐다. 실제 Tab으로 검사하자 기존 포커스 처리의 `preventScroll`이 가로 밖 앱도 화면 밖에 둔다는 접근성 결함을 확인했다.
- 허용된 추가 수정은 검색 결과 안의 키보드 포커스 대상에 한해서만 필요한 가로 거리만큼 목록을 이동한다. 다른 패널의 포커스 처리와 세로 위치는 유지한다. 회귀 검사는 Tab/Shift+Tab으로 모든 결과가 완전히 보이는지, 가로 이동·복귀와 세로 스크롤 0, 설정/Safari 검색어와 Enter의 실제 앱 진입까지 확인한다. Chromium/WebKit 네 조건씩 8개가 통과했다. 시각 허용 오차는 변경하지 않는다.
- `harness/evidence/issue-58/report.json`의 기존 포맷 오류는 조정 에이전트의 허용에 따라 포맷만 수정했다. JSON으로 읽은 내용이 이전 파일과 같음을 확인했다.

## 남은 확인과 제한

검색 접근성 검사 수정 후 전체 브라우저 재실행 결과는 아직 기록하지 않았다. Linux 기준은 조정 에이전트가 실제 CI 캡처로 별도 처리하고, 최종 독립 검토 결과도 별도 기록한다. 실제 iPhone Safari는 검증하지 않았다. macOS 캡처를 Linux 기준으로 복사하지 않는다.
