# Issue 47: 스트림 오류 정리와 전체 재전처리

## 목표

손상 gzip 오류가 호출자에게 전달되지 않는 문제를 수정하고, 기존 8개 원본을 다시 전수 처리한다. UI 작업과 다른 작업 폴더는 이 Issue의 범위가 아니다.

## 순서

1. 고정된 원본 8개를 크기·SHA-256으로 재검증한다.
2. 합성 손상 입력을 별도 프로세스로 재현해 hang·uncaught를 구분한다.
3. 스트림 오류와 종료를 정리하고 정상 입력·읽기/파싱 실패·조기 중단·기존 latest 보존을 검사한다.
4. 전체 원문을 두 번 처리한다. 기존 정규화 내용이 유지되는지와 같은 구현의 두 실행이 동일한지 별도로 확인한다.
5. 실제 결과와 제한을 문서화하고 품질 검사·독립 리뷰·PR 절차로 전달한다.

## 데이터 보존

기존 raw와 processed run을 덮어쓰지 않는다. 새 구현의 fingerprint로 새 run을 게시한다. 구현 fingerprint와 run ID 때문에 달라지는 설정·보고서는 실제 정규화 payload의 동일성 검사와 구분한다. 화자·청자·대화 순서와 학습 적합성을 새로 추정하지 않는다.

대사 후보 분류·검토 산출물 개선은 별도 조사 결과에 따라 독립 단계로 진행한다. 오류 수정 결과의 재현성 검증과 섞지 않는다.
