# Issue 20 시스템 화면과 홈 인디케이터

요구사항·진행 상태의 원본은 [Issue #20](https://github.com/nam9nine/yaku_IPhone/issues/20)이다. 이 문서는 순서와 검증 계획이며 실행 성공 기록이 아니다.

## 목표와 확정된 차이

제어 센터·최근 앱·알림 센터를 직접 확인한 Apple 자료에 맞춰 재구성한다. 큰 제목·X 닫기·설명·상시 보조 바를 제거하고 키보드 조작은 sr-only 또는 포커스 시 노출한다. 실제 앱 미리보기·세션 재개·가로 탐색·위로 닫기를 유지한다.

홈·앱·시스템 패널에 홈 막대를 표시한다. 기본 흰색이며 밝은 앱에서는 검정색으로 대비를 확보한다. 홈·앱에서 일정 거리 끌면 pause 없이 최근 앱을 연다. 최근 앱의 배경·하단 막대 상승·Escape는 홈으로 복귀하고 카드 선택은 앱 상태를 재개한다. 세로 스크롤 금지는 유지한다. 실제 OS의 멈춤과 다른 선택이며 Apple 이미지를 앱으로 붙이지 않는다.

## 작업 순서

1. 기존 제어 센터·최근 앱 reference ID를 재사용한다. 알림 iOS 26 보조 이미지와 인디케이터 공식 문서를 URL·버전·SHA-256·이용 범위와 등록한다. [디자인 근거](../../docs/ios-system-design.md)에 관찰과 불확실성을 남긴다.
2. 연결/미디어 그룹, 원형 도구, Focus와 세로 조절기, 우측 그룹 레일을 재구성한다. 가상 상태와 실기기 제어의 차이를 기록한다.
3. 최근 앱의 긴 겹침 카드와 카드 위 앱 표식, 실제 미리보기를 유지한다. 알림의 임의 빈 상태 장식을 제거하고 버전이 미확인된 모양을 임의로 확정하지 않는다.
4. 홈 인디케이터를 공통 표시·입력 영역으로 정리하고 거리 기준 전환·이동 피드백·취소 복구·dismiss→홈을 연결한다. 뒤의 앱 입력 차단과 상태 보존을 확인한다.
5. 모바일 세 크기·작은 높이·큰 글자·밝은/어두운 앱·reduced motion·키보드·range·입력 충돌·safe area·viewport 변경을 검사한다. 세로 offset은 0을 유지하고 지원 조작 접근이 끊기지 않게 한다.
6. 공식 원본·이전 앱·변경 앱 캡처를 직접 비교한다. 의도된 baseline 변경만 플랫폼별로 생성하고 구현하지 않은 검토자가 diff·완료 조건·캡처를 검토한다.
7. 조정 에이전트가 현재 SHA의 필수 검사·증거를 확인한 뒤 PR·squash·main Pages 배포·공개 URL을 확인한다. 미리 완료로 표시하지 않는다.

## 검증 계획

| 범위               | 명령 또는 확인                        | 기록 원칙                                                               |
| ------------------ | ------------------------------------- | ----------------------------------------------------------------------- |
| 색인 구조          | `npm run harness:check`               | ID·URL·라이선스·해시 구조 검사와 화면 일치 판정 구분                    |
| 로컬 원문          | `npm run refs:fetch -- --verify-only` | 통합 worktree의 SHA·크기 검사. 누락 시 기본 fetch로 복원                |
| 품질               | `npm run check`                       | 실제 SHA와 결과 기록                                                    |
| 제스처·상태        | `npm run test:e2e`                    | pause 없는 진입, 취소·중복 입력·resize 복구, dismiss→홈, 카드→상태 재개 |
| 화면 회귀          | `npm run test:visual`                 | macOS/Linux·Chromium/WebKit 분리, 실패 원인 확인                        |
| 직접 비교          | 원본·before·after 열기                | 도형·비율·재질·글자·불필요 요소·작은 화면 접근성                        |
| 실제 iPhone Safari | 실제 기기에서 별도 실행               | 미수행은 미검증. desktop WebKit/viewport 축소로 대체 표기 금지          |

PR에는 reference ID, 실제로 연 캡처, 사용자 요구에 따른 차이와 미지원 OS 연동을 남긴다. 아직 수행하지 않은 UI 검사·독립 검토·기기 검증·배포는 통과로 적지 않는다.
