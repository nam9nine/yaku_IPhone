# 설정·Safari 기본 조작 구현

사용자 승인 범위: 상세 앱 기능보다 앱 열기, 홈 복귀, 스크롤, 입력과 기본 설정의 반응에 집중한다. 잠금 추가 디자인·전환기·제어 센터·계정·즐겨찾기·방문 기록 관리는 제외한다.

## 전달 순서

1. Issue #12: 잠금과 앱 세션 분리, 아이콘 위치에서 열기/닫기, 전용 홈 제스처, 홈 위치·포커스 복원. 앱 내부는 이 단계에 한해 명시적인 준비 화면이다.
2. Issue #13: 설정 목록/상세와 가상 네트워크, 테마, 웹 밝기, 배경, 글자와 동작 설정. 설정만 프로젝트 전용 localStorage에 저장한다.
3. Issue #14: Safari Compact와 두 샘플 페이지, 탭별 탐색, 주소/제목 검색, 명시적 외부 열기, 가상 네트워크와 입력 높이 연동.

설정과 Safari 구현자는 별도 worktree에서 자신의 앱 디렉터리만 편집한다. root가 공통 상태와 CSS, 테스트/레퍼런스, Git/PR 통합을 담당한다. 독립 검토자는 구현을 맡지 않는다.

## 공통 설계

- 방문한 앱과 홈은 비활성 시 hidden/inert로 입력에서 제외하면서 세션을 유지한다. 앱별 내부 탐색과 스크롤은 해당 컴포넌트에 둔다.
- 홈으로 나갈 때 애니메이션 완료 콜백만 기다리지 않고 제한된 완료 시간을 둔다. OS reduced motion에서는 즉시 전환한다.
- 앱 하단의 지정 영역만 홈 제스처를 받고 본문·입력·슬라이더는 제외한다. pointercancel, capture 손실, blur, visibility, viewport 변화는 드래그를 취소한다.
- 앱 실행용 전체 면 레이아웃을 홈 여백과 분리한다. visualViewport 변화에 앱 하단 조작이 따라가도록 한다. 실제 시스템 바/프레임은 추가하지 않는다.

## 검증 계획

단계별 check/e2e/visual/harness, 세 크기와 두 엔진의 캡처 직접 검토, 최종 SHA 독립 리뷰, 필수 gate와 Pages 배포 확인을 수행한다. 실행 결과는 별도 증거와 Issue/PR에 기록한다. 실제 iPhone Safari 미검증을 자동 검사 결과와 구분한다.
