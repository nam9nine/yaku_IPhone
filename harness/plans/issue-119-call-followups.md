# Issue #119 통화 후속 문자

## 목표

마지마의 끈질긴 관심을 강화하고 하루카·마지마 통화에서 무응답 종료·부재중·거절 뒤 AI 발신 문자를 보낸다. 사용자 입력을 가짜로 생성하지 않고 짧은 후속에 추가 표시 지연을 붙이지 않는다.

## 구현 순서

1. 전화 상태에 마지막 활동 기준 60초·작별 6초와 영속 이벤트 큐, 통화별 UUID를 추가한다.
2. assistant-only API/DB schema 3·중복 방지·같은 FIFO·짧은 생성 경로를 연결한다.
3. UI 백그라운드 접수와 즉시 전달, 다음 대화의 별도 후속 문자 기억을 연결한다.
4. 실제 모델 출력·기억·격리, 브라우저 재접속·무응답 흐름, 관리자 성공/실패 표시를 검토한다.
5. 독립 검토와 로컬 검증 결과를 남기고 승인된 CI 생략 배포를 진행한다.

## 검증 조건

- 입력·음성/추론 대기는 무응답 시간 초기화/유예, 미전송 초안은 무한 유예하지 않는다.
- 부재중/거절/무응답별 한 번만 접수, 같은 UUID·통화 ID 재시도와 새로고침 중복 방지.
- 가짜 user 행 없음, 정상 교환 쌍 유지, 후속 문자는 같은 방문자/인물의 다음 입력에만 포함.
- 한 모델 FIFO, non-thinking 최대 96토큰, 후속의 무작위 표시/푸시 지연 없음.
- 실패/잘림은 원문 이력에서 제외하고 관리자에서 확인 가능.
- 실제 Gemma 시간과 출력, Chromium/WebKit 캡처를 증거로 남긴다. 실제 iPhone/팬 평가와 구분한다.

결과는 계획에 미리 기입하지 않고 `harness/evidence/issue-119/`에 기록한다.
