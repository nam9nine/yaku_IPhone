# Issue #70 — 대화 DB와 기존 기록 이관

## 목적과 범위

Gemma 무설정 채팅 전환의 첫 단계로 대화 원본을 SQLite에 저장한다. 방문자 토큰 해시·정상/실패 요청·원문·검토 자료를 분리하고 기존 JSON을 반복 실행 가능한 방식으로 이관한다. 공개 UI 전환, 모델 실행, RAG, 관리자 서버, Cloudflare 배포는 후속 Issue의 범위다.

## 구현 순서

1. WAL·외래 키·원문 불변 조건과 방문자별 UUID 중복 방지를 스키마로 보장한다.
2. 접수·생성 시작·완료·실패·중단 복구를 각각 짧은 트랜잭션으로 연결한다.
3. 성공 이력과 사용자에게 보일 접수 이력을 분리하고 범위에 묶인 cursor를 제공한다.
4. 소유자 검토 기록과 비밀값 없는 내보내기 저장 인터페이스를 마련한다.
5. 중지한 legacy writer의 snapshot을 출처 해시·ID 기준으로 이관하고 충돌을 격리한다.
6. Backup API로 일일 7개·주간 4개 보존을 구현한다.

## 검증

동시 UUID 재시도, 다른 인물로 같은 UUID 재사용, 완료 트랜잭션 중 오류, 서버 재시작, 범위가 다른 cursor, 실패 출력의 모델 이력 배제, 토큰 활동 만료, 원문 불변, 반복 이관·충돌·누락된 job 갱신, 백업 복구를 CPU 테스트로 확인한다. 통합 서버 검사와 실제 legacy 이관은 후속 운영 연결 단계에서 관찰 결과를 기록한다. 계획의 테스트 항목 자체를 실행 성공으로 간주하지 않는다.

## 완료 판단

현재 diff의 검사·독립 검토·PR gate·병합을 수행한다. DB 기반의 완료를 Gemma 답장·팬 품질 평가·공개 연결 완료로 표현하지 않는다.
