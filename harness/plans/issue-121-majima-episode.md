# 마지마 볼링 사건 구현 계획

사용자 승인: 2026-10-31. 이 문서는 계획이며 성공한 실행 증거가 아니다.

- #121: SQLite schema 4, 방문자별 사건 진행, 취소 가능한 FIFO와 API를 기본 OFF로 제공한다.
- #122: 볼링 원작 근거와 현재 IF를 분리하고 reader 판단·선제 문자 기억·실제 Gemma 평가를 연결한다.
- #123: 기존 iPhone UI에서 선제 문자 → 전화 → 후속 문자 → 휴식을 연결하고 공개 배포를 확인한다.

## 동작 계약

화면 표시·잠금 해제 상태의 유효 사용시간 90초 뒤 초대를 시작한다. 통화·답장 대기는 제외한다. 초대 전달 확인은 읽음이 아니며, 이후 활성 시간 120–180초를 한 번 추첨해 전화 한 번을 준비한다. 부재중·수신 거절·통화 중 무응답은 같은 사건의 AI 후속 문자 한 통 뒤 쉰다. 사용자 입력은 예정 연락을 즉시 보류한다. 수락·보류·취소·거절·사용자 결과 보고는 실제 메시지를 근거로 처리한다.

한 세션에서 볼링을 한 번 자동 시작한다. 종료 후 자동 재시작하지 않는다. 원작 승패·니시다 연락은 이번 방문자의 경험이 아니다. 실제 볼링 게임·니시다 연락처·사진·캐릭터 음성은 제외한다. 새 선제 작업은 OS push에서 제외하며 일반 답장과 통화 후속 push는 유지한다.

## 구현 경계

DB가 사건 진행의 원본이며 브라우저는 10초 활성 보고·전달 확인·통화 결과를 제출한다. 여러 탭은 시간을 합산하지 않고 전화 실행을 한 번만 claim한다. 사용자 요청은 선제 작업을 원자적으로 무효화한 뒤 FIFO에 접수한다. 모델은 한 슬롯을 유지한다. 중단된 작업의 늦은 출력은 감사 기록에만 남긴다.

일반 user/assistant 쌍 계약을 유지하고 실제 assistant-only 발신은 순서가 있는 별도 타임라인으로 reader와 writer에 제공한다. reader가 원문 메시지 ID로 뒷받침한 상태 변경만 적용하고 해석 실패 시 연락 보류를 유지한다.

## 검증과 전달

이관·재실행·원문 해시·외래 키, 두 탭·새로고침·초기화·중복 UUID, 선제 생성 도중 사용자 입력·취소·화면 숨김을 자동 검사한다. 사전 고정 12개 상황 × 최소 4턴을 실제 Gemma로 실행하고 판단·말투·원작/IF 혼동·취소 무시를 분리해서 기록한다. Chromium·WebKit 조작과 캡처 직접 검토 후 독립 리뷰·현재 SHA 필수 gate를 통과해야 병합한다. 실제 iPhone과 팬 평가는 별도다.

API/Worker/Pages를 기능 OFF로 배포한 뒤 새 클라이언트 지원과 공개 실제 대화·연락 흐름을 검증하고 활성화한다. 문제가 있으면 사건 기능만 끄고 일반 대화를 유지한다.
