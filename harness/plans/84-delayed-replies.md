# Issue 84: 문자 답장 지연과 알림

## 범위

Issue 83의 품질 우선 추론을 사용하고 대기 연출은 별도로 처리한다. 요청 UUID에서 10~20초의 랜덤 대기를 정한다. 타이핑은 접수+대기 이후에, 완성 답장은 `max(접수+대기+1.5초, 생성 완료+대기)`에 표시한다. 실패한 출력을 정상 문자로 보여주지 않는다.

메시지 앱을 닫아도 처리하고 새로고침 시 시간을 복원한다. 읽지 않은 표시, 사이트 내 배너·소리·알림센터를 연결한다. OS 알림이 활성화되면 같은 답장의 사이트 내 배너와 소리를 억제한다.

사용자가 요청한 iPhone 잠금 화면 알림은 표준 Web Push로 제공한다. 홈 화면에 앱을 추가한 뒤 사용자가 버튼을 눌러 권한을 허용해야 한다. 서버는 개인별 구독과 완료 답장을 별도의 비공개 DB에서 처리한다. 공개 Worker에는 채팅·구독 API만 노출한다.

## 검증

- 요청별 시간·빠른 완료 숨김·느린 추론·오류·화면 전환·읽음·새로고침을 가상 시계로 검사한다.
- 초기화 시 영속 구독 세대를 먼저 무효화하고, 다른 탭의 늦은 응답이 옛 binding을 되살리지 못하게 검사한다.
- 구독 ID 변경, 브라우저 구독 소실, 중복 Push와 표시 중 초기화의 경합을 검사한다.
- 백엔드는 방문자 소유권, HTTPS 수신 주소 제한, 별도 비밀값 보관, 재시작 복구·유한 재시도를 검사한다. 네트워크 외부 전송의 exactly-once는 보장하지 않는다.
- Chromium·WebKit 전체 동작 검사, 실제 이미지 검토, 기준 변경의 독립 리뷰와 PR gate를 수행한다.
- 공개 사이트·Worker·Mac API를 통합 확인한다. 실제 iPhone OS 알림 수신 여부는 자동 검사와 구분해 기록한다.

일반 mock 브라우저 검사는 Service Worker를 차단해 요청 가로채기 계약을 유지하고, 등록 검사는 별도 허용 검사로 실행한다. Push 전용 Service Worker는 앱 자산을 캐시하지 않는다.
