# Issue 61 — 공개 메시지 UI와 Mac 모델 연결

## 범위

하루카·마지마의 메시지 화면에서 직접 입력하고 Mac 모델의 실제 응답을 받는다.
Issue 56의 학습·추론 실험을 이어 사용하며 다른 인물과 기존 이야기 흐름은 보존한다.
사용자는 공개 GitHub Pages에서 접속하는 방식을 선택했다.

## 구성

- 기존 iPhone 메시지 말풍선·헤더·제스처·safe area를 재사용한다.
- Mac의 Starlette/Uvicorn 서버 한 프로세스에서 모델 하나를 전용 실행 스레드에 올린다.
- HTTPS 임시 터널로 Pages와 연결한다. SSE 대신 작업 제출과 상태 조회를 사용한다.
- 접속 키로 서버가 새 방문자 토큰을 발급하고 이력·작업의 소유권을 서버에서 확인한다.
- 키·토큰·원문·가중치는 Git과 앱 번들에 포함하지 않는다.
- 클라이언트가 임의의 system/history/facts를 모델에 전달하지 않도록 서버에서 입력을 조립한다.
- 요청 크기·대기열·방문자별 동시 작업을 제한하고 같은 request_id의 재시도는 중복 생성하지 않는다.
- 모델·네트워크 오류는 표시하며 고정 답변을 실제 모델 응답으로 대신하지 않는다.

## 진행과 검증

1. 서버와 UI를 독립 worktree에서 구현하고 계약을 맞춘다.
2. CPU 테스트로 인증·이력 격리·작업 소유권·중복 방지·실패 처리를 검사한다.
3. 실제 모델 없이 UI 연결 계약을 브라우저에서 검사한다. 이 결과를 실제 추론으로 표시하지 않는다.
4. 학습·평가 GPU 작업이 끝난 뒤 선택 후보를 서버에 올린다.
5. Chromium/WebKit과 360·390·430 너비에서 입력·한글 조합·대화 이동·홈 복귀·오류·키보드 영역을 확인한다.
6. 캡처를 실제 iPhone 참고 화면과 직접 비교하고 독립 리뷰를 받는다.
7. PR 검사·병합·Pages 배포 후 공개 화면에서 하루카·마지마의 실제 모델 응답을 확인한다.

## 운영 한계

임시 터널은 Mac과 실행 프로세스가 켜져 있어야 한다. 주소는 터널 재시작 시 바뀔 수 있다.
상시 서비스용 도메인·계정 설정과 운영 가용성 보장은 이번 작업에 포함하지 않는다.
실제 iPhone Safari 확인과 팬의 말투 평가는 관찰한 결과로만 표시한다.
