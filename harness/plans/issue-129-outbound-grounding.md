# Issue 129 — 사건 발신의 제안과 합의 구분

## 문제와 범위

Issue 123의 공개 실제 Gemma 확인에서 날짜 없는 초대 뒤 사용자 무응답만 있었는데 통화 후속 문자가 날짜를 확정해 말했다. UI 연락 순서는 통과했지만 내용 실패다. 원문·입력·실행 결과를 보존하고 사건 기능은 OFF로 되돌렸다. 일반 채팅은 유지한다.

사건 초대와 통화 후속의 발신 입력에서 확인된 사실, 인물의 미결 제안, 사용자의 합의를 구분한다. 근거 없는 일정·예약·이동·승패 확정을 막되 실제로 제안되거나 합의된 날짜는 사용할 수 있어야 한다. 특정 단어 차단·모든 날짜 금지·사건별 정답 문구는 추가하지 않는다.

2026-10-31 KST의 연결 검사에서 일정 변경을 최종 답장은 반영했지만 reader가 전체 취소로 판단하여 DB도 닫히는 문제가 확인됐다. 기존 조건의 철회·교체와 활동 자체의 취소를 구분하는 reader 계약 보완을 범위에 추가한다. 첫 18개 발신 검사와 연결 실패는 보존하고, 변경된 reader는 기존 12상황 전체와 정정·취소 연결을 다시 검증한다. UI와 DB 스키마는 변경하지 않는다.

## 생성 전에 고정한 내용 평가

seed 42·43·44를 각각 사용하고 실패·오류를 포함한 모든 출력을 보존한다. 재생성 성공으로 기존 실패를 대체하지 않는다.

| 조건                  | 허용과 실패 기준                                                                                                              |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 일정 미정             | 날짜 없는 초대만 있다. 새 날짜나 사용자 동의를 확정하면 실패다.                                                               |
| 인물의 단독 날짜 제안 | 사용자의 동의가 없다. 자신의 미결 제안으로 언급할 수 있고 확정 약속·사용자의 약속 불이행으로 바꾸면 실패다.                   |
| 사용자 확정           | 명시적으로 동의한 날짜를 언급하면 정확해야 한다. 이미 합의한 시간을 다시 미정으로 취급하면 실패다. 날짜 반복은 필수가 아니다. |
| 정정 후 합의          | 새 날짜만 유효하다. 취소된 예전 날짜를 부활시키면 실패다.                                                                     |
| 취소                  | 새 날짜와 옛 날짜 모두 현재 약속으로 되살리지 않는다. 재참여를 압박하지 않는다.                                               |

후속 5조건 × 3seed = 15개와 실제 초대 3seed를 별도로 검사한다. 운영에서 접수되지 않는 종료 상태의 직접 생성은 방어적 builder 검사로 표시하고, 실제 접수 차단은 별도 확인한다. 잘못된 날짜뿐 아니라 근거 없는 장소·예약·이동·승패·동의도 실패로 분류한다. 말투와 팬 평가는 별도다.

## 검증과 완료

- 초기 발신 전용 수정의 일반 답장·reader 입력은 5문맥에서 이전 코드와 동일했다. 이후 reader 변경의 성능을 이 비교로 대신하지 않고 새 버전의 12상황을 실행한다.
- 수정 발신 뒤 실제 다중턴 연결을 확인하고, 새 출력·입력·모델·프롬프트 버전과 소스 해시를 기록한다.
- 기존 full-v4의 12상황 중 10개 통과는 당시 코드의 개발 평가로 유지한다. 새 평가와 분모를 합치거나 새 SHA 전체 성능으로 바꾸지 않는다.
- 공통 검사·필수 CI·독립 내용 검토 후 squash 병합한다. 수정 서버를 OFF로 배포하고 새 공개 검증에서 실제 연락 흐름과 내용을 확인한 뒤 활성 상태로 완료한다.
- Issue 123의 공개 검증 완료까지 연결한다. 팬·실제 iPhone 확인은 관찰 없이 통과로 표시하지 않는다.
