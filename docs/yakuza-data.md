# 용과 같이 원문 수집과 1차 전처리

이 도구는 공개 MNBVC의 Yakuza 8개 파일을 로컬에 수집하고, 모든 원문을 보존하면서 검토할 자료를 정리한다. **완성된 캐릭터 대화 학습셋을 생성하지 않는다.** 화자·청자·실제 발화 순서를 모르는 행을 AI로 추측하거나 user/assistant로 연결하지 않는다.

## 범위와 저장 위치

[원본 manifest](../references/yakuza-dataset.json)는 Hugging Face revision과 LFS SHA-256을 고정한다. 포함 작품은 3·4·5·6·극2·7·외전·8이다. 0·1·극 등은 이 디렉터리에 없으며 이 수집만으로 시리즈 전체나 특정 인물의 모든 대사가 확보됐다고 할 수 없다.

자료는 기본적으로 ignored `references/local/yakuza-corpus/`에 저장한다. `src/`와 `public/`에 넣거나 앱에서 import하지 않는다. Git에는 코드·메타데이터·집계만 보관하며, 게임 텍스트를 PR·CI artifact·Pages에 게시하지 않는다. 데이터 카드의 MIT 표기를 원 게임 텍스트의 이용 허가로 확대하지 않는다.

## 실행

Node.js 24.22.0을 사용한다. 프로젝트 루트에서 실행한다.

```sh
node scripts/fetch-yakuza.mjs
node scripts/preprocess-yakuza.mjs
```

별도 worktree에서 원본 프로젝트의 로컬 자료를 처리하려면 두 명령 모두 `--data-dir /절대경로/references/local/yakuza-corpus`를 전달한다. 다운로드는 기존 파일도 크기와 SHA-256을 검사한다. 손상된 캐시를 조용히 덮어쓰지 않으며 오류를 보고한다. 중단된 `.part`는 정상 원본으로 취급하지 않는다.

정제 실행은 입력 manifest, 별칭, 구현 코드로 run ID를 만든다. 임시 디렉터리에서 전 파일 처리가 성공한 후에만 결과와 `latest.json`을 게시한다. 같은 명령을 다시 실행하면 전수 재처리한 해시를 기존 결과와 비교한다. 결과가 다르면 기존 파일을 보존하고 실패한다.

gzip 오류는 소비자가 한 행을 받은 뒤 비동기 작업 중이어도 호출자에게 전달한다. 스트림 종료는 정상 완료·파싱 실패·소비 중단 모두에서 기다린다. 손상 입력으로 실행이 실패하면 이전 정상 run과 `latest.json`을 유지하고 처리 lock과 임시 run을 정리한다. [Issue 47 검증](../harness/evidence/issue-47-yakuza-reprocessing.md)은 합성 오류 반복과 실제 8개 원본 재처리를 구분해 기록한다.

## 산출물

| 파일                                                  | 의미                                                                    |
| ----------------------------------------------------- | ----------------------------------------------------------------------- |
| `raw/*.jsonl.gz`                                      | 다운로드한 바이트 그대로의 전체 원문, 모든 언어/메타데이터 포함         |
| `download-receipt.json`                               | 마지막 다운로드/캐시 검증 결과                                          |
| `latest.json`                                         | 마지막 정상 처리 run 위치와 `trainingReady: false`                      |
| `processed/<run>/<game>.normalized.jsonl.gz`          | 입력 한 행당 정제 한 행. 원문 언어·품질 필드·출처·한국어 변경 이유 보존 |
| `dialogue-candidates.jsonl`                           | 한국어 대화/메일 후보의 행 참조. 검증된 대화나 학습 정답이 아님         |
| `quarantine.jsonl`                                    | 한국어 없음·변수·태그·언어 의심 등 검토가 필요한 행 참조                |
| `scenes.jsonl`                                        | 원본 경로로 묶은 장면 후보의 집계. 순서와 분기 미검증                   |
| `names.jsonl`                                         | 이름 관련 경로의 모든 후보. 인물 외 이름일 수 있음                      |
| `mentions.jsonl`                                      | 우선 검토 인물 별칭의 언급. 화자·청자·관계 라벨이 아님                  |
| `review-samples.jsonl`                                | 분류/경고/언급별 최초 표본. 랜덤 표본이나 전체 정확도 추정치가 아님     |
| `report.json`, `configuration.json`, `checksums.json` | 입력·출력 수, 언어/분류/보류 집계, 설정과 결과 해시                     |

원문 행 해시는 줄 끝 LF를 제외한 JSON 문자열을 기준으로 한다. 정제 파일의 원본 행 번호로 `raw`에 돌아갈 수 있다. 정제 결과의 압축 파일은 `gzip -dc` 또는 Python `gzip`으로 읽을 수 있다.

## 정제 원칙

- `是否重复`는 `zh_text` 중복 기준이다. `低质量段落数`도 한국어 품질 점수가 아니다. 두 필드를 보존하지만 한국어 제거 조건으로 사용하지 않는다. [원본 필드 정의](https://github.com/mnbvc-parallel-corpus-team/parallel_corpus_mnbvc#字段定义)
- 빈 한국어, 알 수 없는 언어, 명단 밖 인물도 정제 출력에서 삭제하지 않는다. 한국어가 없는 작품도 다른 언어와 원본을 보존한다.
- Unicode NFC·줄 끝 형식과 확인된 제어 태그만 정리한다. 의미 있는 줄바꿈·말투·사투리·호칭은 유지한다. 알려지지 않은 태그와 변수는 기록하고 검토 대상으로 둔다.
- `rawKey`를 그대로 유지한다. 파싱 결과는 후보이며 테이블 번호를 실제 발화 순번으로 확정하지 않는다. 추출기가 남기지 않은 문맥을 생성하지 않는다.
- 장면 후보는 게임 파일·원본 컨테이너·후보 경로를 함께 사용한다. 서로 다른 테이블의 `message` 같은 같은 이름을 한 장면으로 합치지 않는다. 보관된 게임 파일과 실제 사건이 속한 작품/시점은 다를 수 있어 `storyGame`·`timeline`은 미확인으로 둔다.
- 같은 원본 키와 모든 언어 문자열이 일치할 때만 중복으로 표시하고 원본 행은 남긴다. 다른 장면의 같은 짧은 문장은 합치지 않는다.
- `references/yakuza-characters.json`은 검토 우선순위 목록이다. 키류, 하루카, 마지마, 다이고, 미네, 사에지마, 다테, 아키야마, 니시키 외의 행도 모두 보존한다. 영어 단독 `Mine`·`Date`처럼 일반 단어와 충돌하는 별칭은 사용하지 않는다.
- 한국어 별칭도 다른 단어·상품명에 포함될 수 있어 언급 색인은 사람이 확인할 후보다. 이름 후보에는 점원·군중·물건도 섞일 수 있으며 후보 수를 등장인물 수나 확보한 대사 수로 보고하지 않는다.
- 모든 행의 `speaker`, `recipient`는 아직 `null`이다. 관계·시점·서사 이해는 이 색인 다음에 실제 장면을 확인해 붙일 라벨이다.

## 다음 데이터 단계

`node scripts/review-yakuza.mjs`로 원본 참조·다국어 문구·파생 분류를 함께 담은 [2차 검토 자료](yakuza-review.md)를 생성한다. 이 자료도 아직 화자 라벨이나 SFT 학습 데이터는 아니다.

이름 후보와 장면 후보에서 실제 인물·관계 근거를 검토한다. 새 화자를 확인하면 기존 인물 목록과 관계없이 라벨을 추가할 수 있다. 원작 시점과 다섯 명 이상이 함께 연락 가능한 프로젝트의 팬 창작 설정을 구분한다.

화자·청자·순서·한국어를 검증한 장면에서 원문 대화와 문자 각색을 나눈다. 같은 장면의 모든 언어·각색·요약·대화 window를 같은 train/validation/test 그룹으로 묶는다. 실제 학습 전에는 모델 템플릿과 loss 대상·종료 토큰까지 별도로 확인해야 한다.
