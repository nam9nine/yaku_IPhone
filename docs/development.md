# 개발 절차

## 작업 단위

GitHub Issue가 요구사항·진행 상태·완료 여부의 원본이다. 문서는 절차와 결정의 근거를 설명하고 별도 작업 보드를 만들지 않는다.

Issue에는 목적, 포함/제외 범위, 확인 가능한 완료 조건, 관련 레퍼런스, 검증 방법을 적는다. 화면의 작은 여백 수정까지 별도 Issue를 만들지 않는다. 범위가 달라지면 기존 Issue를 수정하거나 후속 Issue로 분리한다.

작업 브랜치는 `유형/이슈번호-짧은-영문설명`으로 만든다. 커밋은 검토 가능한 논리 단위로 작성하고, PR은 `Closes #번호`로 연결한다. 제목은 `feat: 잠금 화면의 위로 밀기 전환 구현`처럼 영문 prefix와 한국어 설명을 쓴다.

## 시작과 구현

1. 관련 Issue, 루트 AGENTS, 변경 대상 코드를 읽는다.
2. `git status`로 기존 변경과 담당 범위를 확인한다. 공유 작업에서는 조정 에이전트가 Git 작업을 담당한다.
3. 복잡한 작업은 `harness/plans/`에 목표·단계·검증·불확실성을 기록한다. 상태는 Issue에 갱신한다.
4. 작은 동작 단위로 구현한다. 실제 요구가 없는 프레임워크·추상화·의존성은 추가하지 않는다.
5. 완료 조건을 검증하고 결과를 기록한다. 미실행·실패·차단은 성공과 구분한다.

환경은 Node.js 24.22.0, npm, React, Vite, TypeScript strict다. 로컬 Node는 `.tooling/`에 설치하며 저장소에는 포함하지 않는다. lockfile을 유지하고 재현 설치에는 `npm ci`를 사용한다.

검사 명령의 정확한 역할은 [하네스](harness.md)에 모은다. 저장소가 제공하는 명령을 사용하며 동일 작업을 위한 별도 임시 스크립트를 반복해서 만들지 않는다.

## 검토와 병합

PR에는 문제와 최종 동작, 검증 결과, 실제 화면 증거, 남은 차이를 적는다. UI 변경은 [시각 QA](visual-qa.md)를 수행한다. 코드를 작성하지 않은 에이전트가 실제 diff와 완료 조건을 검토한다. 리뷰 지적은 수정하거나 이유와 후속 Issue를 남긴다.

사용자와 에이전트가 같은 GitHub 계정을 쓰므로 자기 PR에 대한 정식 승인 1개를 강제하지 않는다. 독립 에이전트 검토는 PR에 별도로 기록하며 다른 계정의 승인으로 표현하지 않는다.

필수 CI job은 `quality`, `browser`, `evidence`, 최종 `merge-gate`다. gate가 실패하거나 필요한 시각 증거가 없으면 병합하지 않는다. 새 코드 commit 뒤에는 현재 SHA 기준으로 증거와 검토를 갱신한다.

자동 squash merge와 main 병합 후 공개 배포는 사용자에게 승인된 개발 흐름이다. 반복 확인을 요청하지 않고 검증된 PR을 이 흐름으로 전달한다. 범위를 벗어나는 삭제·데이터 변경·새로운 외부 전달은 기존 승인에 포함된 것으로 간주하지 않는다.

## 완료 기준

- Issue의 완료 조건을 충족한다.
- 변경에 맞는 자동 검사와 실제 조작을 수행했다.
- UI가 바뀌면 같은 조건의 기준/결과를 직접 보고 주요 차이를 해결했다.
- 필요한 독립 리뷰를 마쳤고 중대한 지적이 남아 있지 않다.
- PR이 main에 병합되었다.
- 공개 배포 결과와 원본 SHA를 확인했다. 배포 실패는 완료로 숨기지 않고 Issue에 기록한다.

작업 완료 보고는 과정 나열보다 결과·검증·제한을 우선한다. 미완료된 후속 기능이나 실제 기기 확인을 완료라고 표현하지 않는다.

## 병렬 작업과 worktree

쓰기 작업을 맡은 서브에이전트는 조정 에이전트가 준비한 독립 worktree에서만 편집한다. 원본 working tree는 읽기 전용으로 다루며, worktree 안에서도 담당 파일 범위를 지킨다. 읽기 전용 조사·리뷰는 별도 worktree가 필요하지 않다.

조정 에이전트만 브랜치 변경·staging·commit·push·merge와 결과 통합을 수행한다. 담당자는 파일 목록과 검증 결과를 전달하고, 조정 에이전트는 통합 diff를 검토한 뒤 통합 상태에서 필요한 검사를 수행한다. 공통 CSS·설정·package 파일은 한 담당자만 수정한다. 다른 에이전트의 변경을 덮거나 공유 index를 조작하지 않는다.
