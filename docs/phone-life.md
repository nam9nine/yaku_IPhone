# 키류의 폰 문자·전화 흐름

Issue #107은 2026-10-29 첨부 요구를 기존 폰에 적용한다. 외곽 프레임·기존 사진 여섯 장·음악·카라오케·노트·초기화의 DB 보관 동작은 유지한다. 새 대사와 통화 대본은 원작 인물을 참고한 사이트용 IF 창작이며 공식 대사로 표시하지 않는다.

## 문자와 선택

- 마지마는 직접 입력과 짧은 선택 단계를 함께 제공한다. 성공한 문자 세 번마다 남은 선택 단계가 있으면 선택지를 제시한다. 실패한 전송은 이 횟수에 포함하지 않는다. 준비된 세 선택 단계를 마친 뒤에도 성공한 문자 세 번마다 45초 휴식을 둔다. 실패 문자를 고치는 동안에는 선택·휴식 제한을 유예한다.
- 하루카는 완료한 할 일의 보고를 골라 보낸다. 답장은 기존 Gemma를 사용한다. 임의 자유 입력은 제공하지 않으며 과거에 보낸 자유 대화 기록은 보존한다.
- 다이고·사에지마·미네·다테·아키야마·유키는 각기 다른 주제의 세 번 왕복하는 선택형 문자다. 이 여섯 인물의 답장은 미리 작성한 IF 대본이다.
- 타이핑 말풍선은 표시하지 않는다. AI 답장의 기존 무작위 읽음·도착 지연은 유지한다. 로컬 선택형 답장은 사이트가 보이는 동안 6–12초 후 도착한다.
- 연락처 하나에 답장을 기다리는 동안 다른 연락처에 바로 보낼 수 있다. 서버는 방문자·인물·시나리오당 활성 요청 하나, 방문자당 둘, 전체 FIFO 여덟 개를 허용한다. 추론 모델은 한 슬롯에서 순서대로 생성한다.
- 선택형 AI 문자는 실제 성공한 같은 request ID의 답장 이후에만 선택 완료·인연에 반영한다. 실패하거나 잘린 답장은 선택 완료로 계산하지 않는다.

## 인연·전화·할 일

마지마 선택과 통화 반응은 로컬 인연 값 -5…5에 반영된다. -2 이하·2 이상에서 각각 서늘함·친근함의 임시 대화 조건을 사용한다. 마지마 통화를 12초 이상 이어가고 종료하면 +1, 거절·짧은 종료는 -1이며 놓친 전화는 값이 바뀌지 않는다. 이는 구현 기본값이고 원작 관계나 과거 사건을 바꾸는 설정이 아니다. 사용자가 선택할 수 있는 모델 입력은 검증된 세 가지 상태뿐이며 임의 시스템 문장은 받지 않는다.

전화는 인물별 텍스트 대본으로 진행하며 발신·수신·종료·최근 통화를 기록한다. 새 자동 전화는 잠금 해제 상태에서 사이트를 보는 사용 시간으로 예약하고, 숨긴 동안 진행시키지 않는다. 첫 전화는 60초 후, 이후는 120–240초 간격이며 마지마와 다른 인물을 번갈아 배치한다. 마지마는 90–180초 간격의 선제 문자도 보낸다. 여덟 개의 IF 문자는 초기화 전까지 각각 한 번 보내며, 인연이 서먹하면 친근한 선제 문자를 보류한다. AI 답장 대기·통화·숨김·잠금 중에는 새 연락의 시간이 진행되지 않는다. 통화 뒤 문자는 최소 60초, 문자 뒤 전화는 최소 45초를 둔다. 장보기 완료 전화는 별도 한 번 유지한다. 마지마의 거절·이른 종료에는 후속 문자와 다음 전화가 이어진다. 실제 사람과 통화하거나 AI 음성을 생성하는 기능은 아니다.

마지마 수신음은 기존 24시간 신데렐라 0–32초 파일이다. 다른 인물은 기존 알림 녹음 파일을 반복 재생한다. 2026-10-29 사용자 결정으로 통화 중 캐릭터 음성·배우 한마디 재생은 폐기한다. 수신 벨소리만 유지한다.

할 일은 기존 장보기·텃밭·마메에 체육복 이름표·택배를 추가했다. 완료 이벤트는 중복되지 않으며 관련 인물의 문자로 이어진다. 요리 앱 이름은 나팔꽃키친, 택시는 류큐 거리·카무로쵸의 가상 목적지를 선택한다. 니시키는 전화 연락처에서 제외하고 기존 저장된 다른 진행 상태는 유지한다. 원작 RAG에서 니시키라는 인물을 삭제한 것은 아니다.

## 저장·알림·제한

로컬 전화·선택·인연은 기존 day 저장소에서 이전 형식을 이관한다. AI DB v2는 이전 기록·토큰·UUID를 보존하면서 연락처별 활성 요청 제약으로 이관한다. API와 관리자 동시 시작도 SQLite 쓰기 잠금 안에서 버전을 다시 확인한다.

AI 답장 여러 개가 함께 도착해도 각각 수신 확인하고, 새 도착 소리만 한 번씩 재생한다. 로컬 이야기 문자도 도착 시 앱 안 알림·읽지 않음을 표시한다. 채팅방에 있는 동안 상단 배너는 나타나지 않는다. 초기 기록을 읽거나 앱을 열었다는 이유로 소리를 재생하지 않는다. 로컬 대본은 Mac 서버가 생성하지 않으므로 사이트가 닫혔을 때 OS push를 보내지 않는다.

비노골적 대화 원칙은 모델 공통 지침과 명확한 성적 역할극 요청·출력에 대한 좁은 검사로 적용한다. 원작의 싸움, 일반적인 애정 표현, 피해 상담을 일괄 차단하지 않는다. 규칙 검사는 의미 기반 완전 분류기가 아니며 새 표현에 대한 팬·운영자 검토는 계속 필요하다. 차단된 생성은 실패 기록으로 남고 정상 대화 기억에는 들어가지 않는다.

지정 꽃 아이콘·추가 사진 원본은 미확보 상태다. 확인 전에는 대체 생성물을 요청한 원본으로 표시하지 않는다. 친구 한정 공개의 구체적인 접근 정책도 사용자 선택 전까지 기존 무설정 공개 접속을 유지한다. GitHub Pages의 정적 앱 자체를 비공개로 만드는 기능은 이 변경에 포함하지 않는다.

## AI에 전달하는 현재 폰 사건

전화 종료와 퀘스트 체크, 카무로쵸 연락은 승인된 이벤트 ID로 최근 네 개까지 전달한다. 서버는 인물별 허용 ID·중복·개수를 검사하고 같은 버전의 고정 설명으로 바꾼다. 임의 클라이언트 문장이나 다른 인물의 사건은 허용하지 않는다. 원작 사실과 실제 대화 이력이 아닌 현재 IF 상태 보고로 구분하며 최근 대화의 정정이 우선한다. 사건 ID와 해시를 생성 기록에 고정하고 재시도에도 유지한다. 전체 통화 대본을 모두 영구 AI 기억으로 옮기는 기능은 아니다. 구체적인 인과 흐름과 원작 근거는 [이벤트 기획](story-events.md)에 기록한다.

## 사용자의 음성 입력, 캐릭터의 글 답장

2026-10-29 추가 요청에 따라 마지마·하루카와 연결된 통화에서 실제 브라우저 `SpeechRecognition / webkitSpeechRecognition`을 사용한다. 캐릭터 음성 재생·합성은 하지 않는다. 다른 연락처는 기존 선택형 대본 통화다. 하루카의 문자 앱은 퀘스트 중심 그대로이며, 통화에서는 사용자가 직접 말하거나 입력할 수 있다.

- 통화에 응답하는 것만으로 마이크를 켜지 않는다. `녹음 시작`을 눌러 한국어 인식을 시작하고, 권한은 브라우저가 요청한다.
- 중간·최종 인식 문장을 화면에서 확인하고 수정한 뒤 `말 보내기`로 전송한다. 인식 이벤트만으로 자동 전송하지 않는다. 같은 상대의 이전 답장이 대기 중이면 추가 전송을 제한한다.
- 전송한 말과 AI 글 답장은 기존 인물별 DB·RAG·순차 모델 대기열을 공유한다. 통화 전에 보낸 문자의 답장도 통화 화면의 최근 대화에 표시한다. 통화 종료 뒤에도 접수한 요청은 완료하지만 통화 입력과 답장은 문자 목록·채팅방·문자 알림에 표시하지 않는다. DB 원문과 같은 인물의 대화 기억은 유지한다.
- 권한 거부·미지원·네트워크 오류는 직접 입력과 재시도를 제공한다. 30초에 인식을 마무리하며 종료가 늦으면 5초 후 중단한다. 통화 종료·페이지 숨김·이탈 때 중단하고 늦게 온 결과를 다른 통화에 반영하지 않는다.
- 사용자가 마이크를 켠 구간을 MediaRecorder로 녹음하고 인증된 API를 통해 Mac의 `references/local/gemma-chat/state/recordings/<visitor-hash>/<character>/<UUID>.m4a|webm`에 별도 저장한다. 파일 권한은 0600이며 공개 다운로드·문자/RAG 편입은 없다. 최대 30초/2MiB, 방문자당 시간당 30회다. 녹음 시작 버튼과 녹음 중 상태를 표시한다. 취소·종료 시 마이크를 중단하며 이미 녹음한 구간은 저장한다. 업로드 실패는 오류로 표시하며 자동 재시도는 없다. 페이지를 완전히 닫을 때 업로드 완료는 보장하지 않는다. 실제 iPhone에서 인식과 녹음의 동시 실행은 미검증이다. 구현 참고: [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder), [getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia). 브라우저 음성 인식 서비스의 Apple·Google 서버 처리는 별개다.
- Safari 계열에서는 Siri·기기 설정과 지원 여부에 영향을 받는다. 자동화된 대체 API 이벤트 검사는 실제 iPhone 마이크·Siri·PWA 인식 검증이 아니다. 설치된 Mac Chrome에 합성 한국어 WAV를 넣은 별도 진단에서는 인식 서비스 시작 뒤 `no-speech`가 관찰됐고 정확도 검증에 성공했다고 기록하지 않았다.

추가 음성 진단: 설치된 Mac Chrome의 공식 오디오 트랙 입력에 같은 합성 한국어 음성을 전달하고 인식 종료를 요청하자 “형님 오늘 어디에서 만날까요”라는 최종 결과와 정상 종료를 확인했다. 이 결과는 실제 인식 서비스의 합성 입력 검사이며, 물리 마이크나 iPhone·PWA 검증을 대신하지 않는다.
