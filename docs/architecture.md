# 제품 범위와 구조

## 제품 목표

모바일 브라우저에서 iPhone을 탐색하는 듯한 경험을 만든다. 기준 디자인은 iPhone 18 Pro / iOS 27이다. 실제 iOS를 실행하거나 기기의 운영체제를 바꾸는 앱은 아니다.

잠금·홈·설정·Safari에 이어 전화·메시지·메모·사진·미리 알림·캘린더를 키류의 폰으로 연결한다. Issue #30의 최신 콘텐츠·이벤트·저장 계약은 [나팔꽃의 하루](asagao-day.md)를 따른다. 사용자가 기존 스타일 유지를 선택했으므로 iOS 18로 재설계하지 않는다. 실제 전화·문자 통신이나 시간에 따른 스토리 자동 진행은 포함하지 않는다.

현재 실제 iPhone Safari에서 확인한 결과는 없다. 브라우저 에뮬레이션, 데스크톱 WebKit, 실제 iPhone Safari의 검증 결과를 구분한다.

## 구현 방향

Vite의 정적 React 앱과 TypeScript strict를 사용한다. GitHub Pages의 프로젝트 경로 `/yaku_IPhone/`에서 동작해야 하므로 자산 URL은 Vite base를 존중한다. 현재 서버·계정·외부 API·복잡한 라우터는 필요하지 않다.

공통 컨테이너는 `src/components/MobileShell.tsx`, 디자인 토큰은 `src/styles/tokens.css`, 날짜·시계 데이터는 `src/display/`에 구현했다. `src/App.tsx`가 최초 잠금·홈·재잠금 상태를 소유하며 `src/lock/LockScreen.tsx`와 `src/home/HomeScreen.tsx`를 조합한다. 홈에 들어가면 제목에 포커스를 옮기고 다시 잠그면 해제 버튼에 포커스를 돌려준다.

홈의 앱 데이터는 `src/home/apps.ts`, 자체 SVG 아이콘은 `AppIcon.tsx`, 페이지 이동 판정은 `pageGesture.ts`로 나눈다. 수평 이동 거리가 페이지 폭의 18% 또는 48px 중 큰 값을 넘어야 한 페이지 이동한다. 수직 이동·취소·포커스 손실은 페이지를 유지하고 드래그 후의 앱 클릭은 억제한다. 비활성 페이지는 `inert`이며 페이지 버튼과 화살표 키를 대체 조작으로 제공한다. 홈 전체는 고정되며 `homeLayout.ts`가 높이·실측 앱 행 크기에 맞춰 가로 페이지를 늘리고 Dock을 유지한다. 위젯이 영역보다 크면 위젯을 생략하고 해당 앱 아이콘 접근은 보존한다. 확대된 라벨은 줄바꿈하고 위젯 최소 높이를 글자 크기에 맞춰 늘린다. 자산 출처는 [홈 자산 기록](assets-home.md)에 남긴다.

| 책임                 | 내용                                                                                                                       |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 화면 컨테이너        | viewport, safe area, 배경, 화면 상태                                                                                       |
| 잠금 화면            | 날짜·시계·하단 제어·해제 안내                                                                                              |
| 홈 화면              | 앱 grid, Dock, 페이지 표시                                                                                                 |
| 브라우저와 화면 경계 | safe area, viewport, 앱 내부 조작 영역; 실제 기기가 제공하는 상태바·Dynamic Island·기기 프레임을 웹에 중복으로 그리지 않음 |
| 토큰·데이터          | 색상, 치수, motion, 앱 이름·아이콘, 표시할 콘텐츠                                                                          |

초기 화면 상태는 `locked → unlocking → home` 정도로 시작한다. 실패하거나 취소한 gesture가 중간 상태에 남지 않도록 한다. 실제 Face ID·카메라·전화 동작이 없으면 동작하는 것처럼 보고하지 않는다.

실제 해제 reducer는 `locked → dragging → unlocked`이며 96px 이상 위로 이동한 뒤 놓으면 완료한다. 수평 우세·짧은 이동·pointercancel·capture 손실·포커스 손실은 취소한다. ref가 동기 전이를 보존해 반복 입력으로 콜백이 중복 실행되지 않는다. React 화면 교체는 애니메이션 종료 이벤트에 의존하지 않으며 reduced motion에서도 즉시 완료한다.

모바일 전용 경험을 우선한다. 큰 화면에서도 별도의 macOS UI를 만들지 않으며, 모바일 화면의 배치와 비율을 보존하는 미리보기로 다룬다.

## 레퍼런스 사용

macos-portfolio는 홈 grid·Dock·상태바의 구조와 후속 앱의 참고 자료다. 전체 Next.js 앱, desktop window store, Siri, 날씨 연동을 가져오지 않는다. 그 코드의 `LockScreenTimeWidget`는 홈 안의 시계이며 완성된 잠금 화면이 아니다.

BymanOS는 작은 앱 registry와 모바일 컴포넌트 구조를 참고한다. 포트폴리오 hero card·검색 버튼을 실제 iPhone 홈 기준으로 오인하지 않는다.

ios27-design-system은 재질·색상·치수 참고 자료다. React 패키지는 잠금/홈 완성 화면을 제공하지 않는다. 일부 recipe는 이전 OS·기기 자료를 이어받으므로 이름에 iOS 27이 있다는 이유만으로 최신 화면의 정확한 사양으로 채택하지 않는다.

프레임·glass 라이브러리는 필요한 표현만 검토한다. 웹 화면에 가짜 상태바·Dynamic Island는 추가하지 않는다. 최신 요청에 따라 큰 PC 화면에는 중앙 휴대폰 프레임을 표시하고 모바일은 화면을 채운다. `useViewport`가 앱·시스템 패널과 같은 경계를 계산하며 시스템 제스처는 프레임 안의 로컬 좌표로 판정한다. 화면 아래의 실제 시스템 제스처 영역은 safe area로 보존한다.

## 자산과 접근성

현재 배경은 `src/day/media.ts`의 로컬 사진·창작 그림이다. 가로 식사 장면에는 위쪽 흐림 연장 배경을 두어 시계와 얼굴이 겹치지 않게 하고, 홈에서는 같은 사진을 흐리고 어둡게 표시한다. 사진별 위치 조정은 설정에 저장한다. 이전 `silver-fold.svg`는 초기 구현의 창작 자산 기록이며 현재 기본 배경으로 사용하지 않는다. 출처·버전·사용 조건은 [이미지 기록](asagao-assets.md)을 따른다.

컨테이너는 `visualViewport` 높이(미지원 시 innerHeight)로 고정한다. 설정 목록은 세로로 스크롤한다. Safari에서 문자가 커져 넘치는 본문은 가로 페이지로 나눈다. 네 방향 `env(safe-area-inset-*)`에 기본 여백을 더하며 고정 기기 inset을 가정하지 않는다. 설정 본문은 세로 스크롤 영역과 화면별 위치 ref로 관리한다. 문서·홈·Safari의 세로 overflow를 clip하며 Safari의 필요한 내용은 `PagedContent`의 CSS column과 페이지 조작으로 접근한다. 관련 기준: [MDN viewport 단위](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length), [WebKit safe area 안내](https://webkit.org/blog/7929/designing-websites-for-iphone-x/).

표시 날짜·시계는 브라우저 언어·시간대와 관계없이 `ko-KR` / `Asia/Seoul`로 포맷한다. Issue #30부터 실제 시각 대신 토요일 16:40의 가상 하루를 고정하며 기기 시각 변경에 따라 이벤트가 발생하지 않는다. 시계는 시스템 글꼴이며 Apple의 SF 폰트를 배포하지 않는다. 검증 전용 화면이나 공개 URL 디버그 모드는 없다.

앱에 사용하는 이미지·아이콘·폰트의 출처를 기록한다. 외부 저장소의 MIT 코드 라이선스와 개별 자산의 출처를 구분한다. 기본 시스템 폰트 및 필요한 원본 자산만 사용하고, 레퍼런스 전체를 `public/`에 복사하지 않는다.

터치 외에 키보드로 수행할 수 있는 대체 동작, 아이콘의 접근성 이름, 충분한 터치 영역, reduced motion을 제공한다. 전체 배경에 무거운 glass 효과를 겹쳐 적용하지 않고 작은 제어 영역에서 가독성과 성능을 확인한다.

## 공통 앱 실행과 복귀

`src/shell/session.ts`의 ShellState는 잠금 여부와 실행 앱을 분리한다. 설정·Safari는 최초 실행 이후 세션 동안 유지하고 비활성 앱에는 hidden/inert를 적용한다. 홈도 유지하여 가로 페이지를 보존하며 실행 아이콘에 포커스를 복원한다. 재잠금 해제 시 해당 아이콘이 비활성 페이지에 있으면 홈 제목으로 돌아간다.

`AppWindow`는 아이콘 위치를 기준으로 열기/닫기 애니메이션과 visualViewport 크기를 처리한다. 하단 전용 영역에서 96px 이상 올리고 바로 놓기, 홈 버튼, Alt+Home이 같은 복귀 동작을 실행한다. 올린 뒤 220ms 멈추면 최근 앱으로, 하단 수평 이동은 이전/다음 앱으로 전환한다. 본문에는 홈 제스처를 적용하지 않는다. 거리 부족·방향 기준 밖 대각선·취소·capture 손실·resize·blur 입력은 현재 앱에 머문다. 애니메이션 취소/종료 누락에도 복귀가 완료되고 동작 줄이기에서는 즉시 전환한다.

## 기기 환경 설정

`DevicePreferences`는 가상 연결·테마·밝기·배경·글자 크기·동작 줄이기만 보관한다. `yaku-iphone.preferences.v1` 저장값은 버전과 모든 필드를 검증하며 잘못된 값은 기본값으로 돌아간다. 저장 실패 시 현재 세션에서는 사용할 수 있고 설정 화면에 저장 범위를 안내한다. 앱 내부 화면·탭은 저장하지 않는다.

비행기 모드는 Wi-Fi를 끄고 셀룰러의 실효 연결을 차단한다. 셀룰러 선호는 보존해 비행기 모드를 끄면 복원하며 Wi-Fi는 별도로 다시 켤 수 있다. `isOnline`은 Wi-Fi 또는 비행기 모드가 아닌 활성 셀룰러만 사용한다. Bluetooth는 연결 판정과 무관하다.

`useAppearance`는 시스템 테마·동작 줄이기를 구독하고 텍스트 선택을 rem 기준에 적용한다. 시스템의 동작 줄이기는 사용자가 해제할 수 없다. 밝기는 pointer-events가 없는 검은 덮개로 웹 화면만 어둡게 하며 고정 앱 창의 좌표계를 바꾸는 상위 filter를 사용하지 않는다. 단색 배경에서는 기본 이미지와 시계 전경 덮개를 함께 숨긴다.

설정 아이콘은 이 프로젝트에서 SVG로 작성했다. Apple 공식 이미지는 둥근 그룹·아이콘·행 간격을 비교하는 로컬 참고이며 앱에 복사하거나 배포하지 않는다.

## 키류의 앱과 로컬 기록

`src/story/data.ts`의 조사 기반 인물과 팬 창작 내용을 분리해 [스토리·자산 출처](kiryu-story.md)에 기록한다. 다섯 인물의 연락처에서 메시지 앱의 대화를 선택한다. `App`의 선택 상태가 앱 사이 이동을 연결하고 공통 `AppWindow`가 최근 앱·홈·높이 변경을 처리한다. 네 앱의 본문은 자체 세로 스크롤을 소유하며 문서·홈은 고정된다.

공유 이벤트는 `yaku-iphone.day.v1`, 일반 메모와 사진 즐겨찾기는 `yaku-iphone.story.<key>.v1`에 저장한다. 구조 검사를 통과한 값만 복원하고 저장 실패는 세션 메모리로 처리한다. 메시지는 미리 작성한 선택형 답장과 한 번만 실행하는 반응이며 실제 SMS나 서버 전달은 없다. 이미지 출처와 현재 사용 범위는 [자산 기록](asagao-assets.md)에 남기며 외부 핫링크를 사용하지 않는다.

## Safari 세션과 탐색

`src/safari/navigation.ts`는 탭별 history/index/pageIndex과 실패한 pending 동작을 보관한다. 탭을 닫거나 앱을 전환해도 다른 탭 기록은 유지하며, 마지막 탭을 닫으면 빈 시작 탭을 만든다. 전체 새로고침에서는 세션이 초기화된다.

`pages.ts`가 기존 안내·예제 URL과 카레·바느질·도시락의 가상 페이지, 저장된 검색과 제목 검색을 해석한다. http(s) 외의 스킴과 사용자 인증정보가 들어간 주소는 실행하지 않는다. 외부 주소는 자동 이동·iframe·프록시 없이 명시적 noopener/noreferrer 링크로 안내한다. 가상 연결이 없으면 기존 페이지를 보존하고 새 이동/뒤/앞/새로고침의 pending 동작을 재시도한다.

Compact 주소 막대는 사용자가 누르면 React DOM을 동기 반영한 뒤 해당 이벤트 안에서 입력 포커스를 준다. [WebKit의 사용자 제스처/키보드 구분](https://bugs.webkit.org/show_bug.cgi?id=195884#c4)을 고려한 구현이며 실제 iPhone 키보드 확인을 뜻하지 않는다. visualViewport 높이/offset 변경은 공통 AppWindow가 반영한다.

페이지 메뉴는 Safari 안의 일반 레이어다. 메뉴 아래 본문과 도구막대만 inert 처리하고 공통 하단 홈 제어를 유지한다. 밝기 덮개도 메뉴에 적용된다. Escape는 활성 메뉴에만 등록하며 닫은 뒤 메뉴 버튼에 포커스를 돌린다. 상세 페이지와 아이콘·그림은 이 프로젝트에서 CSS/SVG로 작성했고 Apple 콘텐츠를 앱에 복사하지 않았다.

## 시스템 제스처와 가로 본문

[제스처 조사 및 동작표](gestures.md)를 따른다. `systemGesture.ts`는 시스템 시작 영역의 거리·방향·멈춤을 판정하고 `useSystemGesture`가 capture·취소 수명주기를 관리한다. `SystemPanels`는 제어 센터·최근 앱·알림·검색을 표시한다. 뒤의 화면은 inert로 입력을 차단하며 패널은 키보드 포커스를 내부에 유지한다. 제어 센터는 `DevicePreferences`를 설정 앱과 공유한다.

`ShellState.visited`는 가장 최근 사용 순서다. 빠른 왕복 전환 중에는 별도 `switchOrder`를 유지해 순서 갱신으로 앞뒤 이동이 뒤틀리지 않게 한다. 최근 앱에서 닫기를 선택하면 해당 keyed 인스턴스만 제거한다. 미리보기는 기존 DOM의 inert 복사이며 두 번째 React 앱·이벤트·중복 ID·radio name을 만들지 않는다.

`src/navigation/`은 가로 본문과 앱 가장자리 탐색을 공유한다. 설정의 뒤로 가기는 방문 스택을 pop하고 Safari는 열린 UI 층을 먼저 닫은 뒤 탭 기록을 이동한다. CSS column은 텍스트를 가로 화면으로 나누고 개별 조작 행은 분할하지 않는다. 페이지 버튼과 키보드 포커스 이동으로 모든 내용에 접근하며, Safari는 탐색 기록 항목마다 가로 위치를 유지한다.
