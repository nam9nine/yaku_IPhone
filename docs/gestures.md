# 제스처와 고정 화면

Issue #18에서 사용자가 확정한 정책은 **앱 본문을 포함한 모든 세로 스크롤 금지**, **짧은 하단 상승은 홈, 상승 후 멈춤은 최근 앱**이다. 실제 iPhone에서는 앱 본문이 세로로 스크롤된다. 이 프로젝트에서는 긴 내용을 가로 페이지로 나누는 사용자 맞춤 동작을 적용한다.

## 동작 표

| 시작 위치 / 입력                                | 동작                            | 대체 조작                      |
| ----------------------------------------------- | ------------------------------- | ------------------------------ |
| 오른쪽 상단에서 아래                            | 제어 센터                       | 제어 센터 버튼, Alt+C          |
| 왼쪽 상단에서 아래                              | 알림 센터(현재 알림 없음)       | 키보드 포커스 버튼, Alt+N      |
| 홈 본문에서 아래                                | 지원 앱 검색                    | 키보드 포커스 검색 버튼, Alt+S |
| 앱 하단에서 기준 거리 이상 올리고 바로 놓기     | 홈으로 복귀                     | 홈 버튼, Alt+Home              |
| 하단에서 위로 이동한 뒤 멈추고 손 떼기          | 최근 앱                         | 최근 앱 버튼, Alt+A            |
| 하단에서 좌우                                   | 최근 실행 앱 간 이동            | 최근 앱 카드 선택              |
| 최근 앱 카드 좌우                               | 다른 카드 보기                  | 카드 이동 버튼·키보드          |
| 최근 앱 카드 위                                 | 해당 앱 닫기, 세션 초기화       | 앱 닫기 버튼                   |
| 앱 왼쪽 안쪽 가장자리에서 오른쪽                | 현재 UI 층 닫기, 또는 이전 화면 | 뒤로 버튼                      |
| Safari 오른쪽 안쪽 가장자리에서 왼쪽            | 탐색 기록 앞으로                | 앞으로 버튼                    |
| 본문 좌우                                       | 긴 내용의 가로 페이지 이동      | 이전/다음 내용 버튼            |
| 열린 시스템 화면 하단에서 위 / 배경 탭 / Escape | 시스템 화면 닫기                | 닫기 버튼                      |

왼쪽 뒤로 가기는 설정의 실제 방문 스택을 따른다. Safari에서는 입력·메뉴·탭·오류 안내를 먼저 닫고, 그 다음에 탐색 기록을 이동한다. 설정의 첫 화면에서는 더 뒤로 이동하지 않는다. 홈으로 돌아가기는 별도 하단 제스처다.

## 입력 소유권과 취소

상단 양쪽 35%의 높이 18px, 앱 하단 44px는 시스템 제스처가 담당한다. 앱 내부의 뒤로 가기는 OS 바깥 가장자리를 피한 안쪽 8–32px에서 시작한다. 같은 입력을 본문 페이지 이동과 중복 처리하지 않는다. 이 수치는 Apple의 비공개 기준을 복제한 값이 아니라 웹에서 시험하는 프로젝트 값이다.

하단 상승 96px, 아래 당김 64px, 빠른 앱 전환 80px, 멈춤 220ms를 초기 기준으로 사용한다. 충분히 올라간 후 손을 떼기 전 마지막 유의미한 움직임 시각을 기준으로 멈춤을 판단한다. 짧은 거리의 입력, 방향 기준을 벗어난 대각선, pointercancel, 캡처 손실, 두 번째 손가락, blur, 숨김, 높이 변경은 진행 중 입력을 취소한다. 입력 요소·슬라이더·텍스트 선택은 앱 가장자리 탐색이 가로채지 않는다. `touch-action: pinch-zoom`으로 세로 팬을 막고 브라우저 확대는 허용한다.

최근 앱은 가장 최근 사용 순서(MRU)와 앱 세션을 유지한다. 카드를 닫으면 그 앱 인스턴스만 제거하며, 설정 저장값은 유지된다. 시스템 화면 뒤의 앱은 보일 수 있지만 입력·전역 키보드 동작에서 제외된다. 키보드와 작은 화면에서는 visualViewport에 맞춰 재배치한다.

## 조사 자료와 차이

2026-10-23에 공식 자료 원문과 이미지를 `references/upstream/`에 보관하고 `references/manifest.json`에 URL·SHA-256·사용 목적을 고정했다.

- [Apple 기본 제스처](https://support.apple.com/en-in/guide/iphone/iph75e97af9b/27/ios/27): 탭·길게 누르기·쓸기·스크롤·확대. 지원 앱 외의 편집·사진 확대·드래그 정렬 기능은 이번 범위가 아니다.
- [Apple 앱 전환](https://support.apple.com/en-ca/guide/iphone/iph1a1f981ad/27/ios/27): 아래에서 올려 멈춘 뒤 손 떼기, 하단 가로 전환.
- [Apple 제어 센터](https://support.apple.com/en-ie/guide/iphone/iph59095ec58/27/ios/27): 오른쪽 위에서 내리기, 아래에서 올려 닫기. 실제 제어 센터의 Wi-Fi·Bluetooth는 연결만 일시 해제할 수 있지만, 여기서는 설정 앱과 공유하는 가상 켜기/끄기 상태다.
- [Apple 알림 센터](https://support.apple.com/en-euro/guide/iphone/iph6534c01bc/27/ios/27): 왼쪽 위에서 아래로 쓸기. 실제 알림·계정 연동은 없다.
- [Apple interactive pop](https://developer.apple.com/documentation/uikit/uinavigationcontroller/interactivepopgesturerecognizer): 탐색 스택의 이전 화면으로 돌아가는 가장자리 제스처.
- [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action): 브라우저와 앱의 입력 소유권은 입력 시작 전에 결정되므로 시작 영역별 정책과 취소 처리를 함께 적용한다.

웹 페이지는 iPhone의 실제 제어 센터·홈·Safari 기록 제스처를 대체할 수 없다. 화면 바깥 가장자리에서 OS가 먼저 가져가는 입력은 이 페이지가 받지 못할 수 있다. 따라서 안쪽 시작 영역과 버튼을 함께 제공한다. Playwright Chromium touch 및 데스크톱 WebKit pointer 검증과 실제 iPhone Safari 검증은 별도로 기록한다. 실기기·실제 소프트 키보드 검증은 아직 수행하지 않았다. 검색 진입은 입력창을 자동 포커스하지 않으며 탭하거나 키보드로 입력창을 선택한 뒤 입력한다.
