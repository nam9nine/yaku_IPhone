# 제스처와 고정 화면

[Issue #20](https://github.com/nam9nine/yaku_IPhone/issues/20)의 최신 사용자 요구로 홈·앱·시스템 패널에 홈 인디케이터를 표시한다. 기본 흰색이며 밝은 앱에서는 대비를 위해 검정색으로 바꾼다. 홈·앱의 막대를 위로 기준 거리 이상 끌면 **멈춤 없이 최근 앱**을 연다. Issue #18의 짧은 상승은 홈, 상승 후 멈춤은 최근 앱이라는 구분은 이 변경으로 대체한다.

**앱 본문을 포함한 모든 세로 스크롤 금지**는 유지한다. 실제 iPhone의 앱 본문·알림 목록은 세로로 스크롤되지만 이 체험의 긴 내용은 가로 페이지로 나눈다. 공식 화면 관찰과 의도적인 차이는 [시스템 디자인 근거](ios-system-design.md)를 따른다.

## 동작 표

| 시작 위치 / 입력                                      | 동작                            | 대체 조작                           |
| ----------------------------------------------------- | ------------------------------- | ----------------------------------- |
| 오른쪽 상단에서 아래                                  | 제어 센터                       | 포커스 시 표시되는 버튼, Alt+C      |
| 왼쪽 상단에서 아래                                    | 알림 센터(현재 알림 없음)       | 키보드 포커스 버튼, Alt+N           |
| 홈 본문에서 아래                                      | 지원 앱 검색                    | 키보드 포커스 검색 버튼, Alt+S      |
| 홈·앱의 하단 막대에서 위로 기준 거리 이상 이동        | 멈춤 없이 최근 앱               | 포커스 시 표시되는 버튼, Alt+A      |
| 하단에서 좌우                                         | 최근 실행 앱 간 이동            | 최근 앱 카드 선택                   |
| 최근 앱 카드 좌우                                     | 다른 카드 보기                  | 포커스 시 표시되는 이동 버튼·방향키 |
| 최근 앱 카드 탭                                       | 해당 앱의 실제 세션 재개        | 카드 키보드 선택                    |
| 최근 앱 카드 위                                       | 해당 앱 닫기, 세션 초기화       | 포커스 시 표시되는 앱 닫기 버튼     |
| 앱 왼쪽 안쪽 가장자리에서 오른쪽                      | 현재 UI 층 닫기, 또는 이전 화면 | 뒤로 버튼                           |
| Safari 오른쪽 안쪽 가장자리에서 왼쪽                  | 탐색 기록 앞으로                | 앞으로 버튼                         |
| 본문 좌우                                             | 긴 내용의 가로 페이지 이동      | 이전/다음 내용 버튼                 |
| 최근 앱의 배경 탭 / 하단 막대 위 / Escape             | 홈으로 복귀                     | 포커스 시 표시되는 닫기 버튼        |
| 제어 센터·알림 센터·검색의 하단 위 / 배경 탭 / Escape | 해당 패널 닫기                  | 포커스 시 표시되는 닫기 버튼        |

왼쪽 뒤로 가기는 설정의 실제 방문 스택을 따른다. Safari에서는 입력·메뉴·탭·오류 안내를 먼저 닫고, 그 다음에 탐색 기록을 이동한다. 설정의 첫 화면에서는 더 뒤로 이동하지 않는다. 홈 복귀는 최근 앱의 dismiss 또는 접근성 대체 조작으로 수행한다.

## 입력 소유권과 취소

상단 양쪽과 하단에는 시스템 제스처 시작 영역을 둔다. 하단 막대의 보이는 두께와 터치 영역을 같게 만들지 않는다. 앱 내부 뒤로 가기는 OS 바깥 가장자리를 피한 안쪽에서 시작하고 같은 입력을 본문 페이지 이동과 중복 처리하지 않는다. 시작 영역·거리·방향 임계값은 구현의 공통 값과 검증 기록을 기준으로 하며 Apple의 비공개 임계값이라고 표현하지 않는다. Issue #18의 220ms 멈춤 조건은 최근 앱 진입 조건에서 제거한다.

이동 중에는 막대와 화면/카드가 손가락 이동에 반응한다. 짧은 거리, 방향 기준을 벗어난 대각선, pointercancel, 캡처 손실, 두 번째 손가락, blur, 숨김, viewport 변경은 진행 중 입력을 취소하고 처음 상태로 복구한다. 입력 요소·슬라이더·텍스트 선택은 앱 가장자리 탐색이 가로채지 않는다. `touch-action: pinch-zoom`으로 세로 팬을 막고 브라우저 확대는 허용한다.

최근 앱은 MRU 순서와 앱 세션을 유지한다. 카드 선택은 새 앱을 만드는 동작과 구분하며 설정의 방문 위치와 Safari 탭·입력·탐색 상태를 재개한다. 카드를 닫으면 해당 세션만 제거하고 저장된 설정값은 유지한다. 최근 앱을 dismiss하면 이전 앱이 아닌 홈으로 간다. 시스템 화면 뒤의 앱은 입력·전역 키보드 동작에서 제외한다. 키보드와 작은 화면에서는 visualViewport에 맞춰 재배치한다.

큰 제목·상시 X·설명·하단 보조 바를 화면에서 제거해도 접근성 이름, dialog 제목, 포커스 복귀와 키보드 대체 조작은 유지한다. 대체 조작은 sr-only 또는 포커스 시 표시 방식으로 제공한다.

## 조사 자료와 차이

2026-10-24에 공식 원문과 이미지를 다시 확인했다. `references/manifest.json`의 URL·버전·SHA-256·원문 경로와 [직접 관찰 기록](ios-system-design.md)을 사용한다.

- [Apple 기본 제스처](https://support.apple.com/en-in/guide/iphone/iph75e97af9b/27/ios/27): 탭·길게 누르기·쓸기·스크롤·확대. 지원 앱 외의 편집·사진 확대·드래그 정렬 기능은 이번 범위가 아니다.
- [Apple 앱 전환](https://support.apple.com/en-ca/guide/iphone/iph1a1f981ad/27/ios/27): 아래에서 올려 중앙에서 멈춘 뒤 손 떼기, 하단 가로 전환. 이 체험은 사용자 요구로 멈춤 없는 거리 기준 진입을 사용한다.
- [Apple 홈 인디케이터](https://developer.apple.com/documentation/uikit/uiviewcontroller/prefershomeindicatorautohidden): 시스템이 표시를 숨길 수 있는지 다룬다. 공식 잠금 이미지에는 흰 막대가 있지만 제어 센터·최근 앱 이미지에는 보이지 않는다. 모든 대상 화면에 표시하는 이번 막대는 사용자 요구다.
- [Apple 제어 센터](https://support.apple.com/en-ie/guide/iphone/iph59095ec58/27/ios/27): 오른쪽 위에서 내리기, 아래에서 올려 닫기. 실제 제어 센터의 Wi-Fi·Bluetooth는 연결만 일시 해제할 수 있지만, 여기서는 설정 앱과 공유하는 가상 켜기/끄기 상태다.
- [Apple 알림 센터](https://support.apple.com/en-euro/guide/iphone/iph6534c01bc/27/ios/27): 왼쪽 위에서 아래로 쓸기. 실제 알림·계정 연동은 없다.
- [Apple interactive pop](https://developer.apple.com/documentation/uikit/uinavigationcontroller/interactivepopgesturerecognizer): 탐색 스택의 이전 화면으로 돌아가는 가장자리 제스처.
- [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action): 브라우저와 앱의 입력 소유권은 입력 시작 전에 결정되므로 시작 영역별 정책과 취소 처리를 함께 적용한다.

웹 페이지는 iPhone의 실제 제어 센터·홈·Safari 기록 제스처를 대체할 수 없다. 화면 바깥 가장자리에서 OS가 먼저 가져가는 입력은 이 페이지가 받지 못할 수 있다. 따라서 안쪽 시작 영역과 버튼을 함께 제공한다. Playwright Chromium touch 및 데스크톱 WebKit pointer 검증과 실제 iPhone Safari 검증은 별도로 기록한다. 실기기·실제 소프트 키보드 검증은 아직 수행하지 않았다. 검색 진입은 입력창을 자동 포커스하지 않으며 탭하거나 키보드로 입력창을 선택한 뒤 입력한다.
