# 대사 검토용 2차 전처리

이 단계는 [1차 정규화](yakuza-data.md)를 입력으로 받아 원문을 확인하고 주석을 붙일 자료를 만든다. 모든 행은 대사 검토 후보 또는 별도 보류 파일 중 한 곳에 남는다. 여기서 후보란 **사람이 대사와 문맥을 검토할 대상**이며 학습 정답을 뜻하지 않는다.

## 실행과 위치

```sh
node scripts/review-yakuza.mjs --data-dir /절대경로/references/local/yakuza-corpus
```

기본 입력은 `latest.json`이 가리키는 정상 정규화 run이다. `--input-run <24자리 run ID>`로 과거 run을 지정할 수 있다. `--seed`와 `--samples-per-stratum`으로 결정론적 표본 설정을 명시하며 기본값은 `yakuza-review-v1`, 3개다.

입력 설정·파일 checksum·원본 참조와 행 수를 확인한 뒤 처리하고, 입력이 실행 중 바뀌지 않았는지도 다시 검사한다. 출력은 `reviews/<runId>/`이며 정상 완료 후 `latest-review.json`을 갱신한다. 기존 `latest.json`, raw, 정규화 run은 수정하지 않는다. 같은 명령을 다시 실행하면 전수 재처리 결과를 기존 결과와 대조한다.

| 파일                                                  | 용도                                                                       |
| ----------------------------------------------------- | -------------------------------------------------------------------------- |
| `review-candidates.jsonl`                             | `dialogue_context_review` 행의 출처·다국어 텍스트·미검증 라벨              |
| `review-held.jsonl`                                   | 메일·게임 진행 문맥·UI·이름·언어/품질 보류 등 나머지 모든 행               |
| `duplicate-groups.jsonl`                              | `ko` 열 정제 문자열이 정확히 같은 행의 같은 문맥/다른 문맥 그룹. 삭제 없음 |
| `review-samples.jsonl`                                | 게임·분류·인물 언급·분류 사유·언어 경고별 SHA-256 검토 표본                |
| `configuration.json`, `report.json`, `checksums.json` | 입력 run과 checksum, 실행 설정, 집계 및 출력 검증 정보                     |

텍스트를 포함한 결과는 ignored 로컬 자료다. 공개 Git·앱 번들·CI artifact에 넣지 않는다. 다국어 원문 전체는 정규화 파일에 남고 검토 파일에는 한국어 raw/clean, 일본어, 영어를 함께 싣는다.

## 분류 기준

분류는 정규화의 원래 판단을 덮어쓰지 않고 `lane`과 이유를 추가한다.

- 대사 후보 중 source scene 경로에 독립된 `minigame`, `tutorial`, `shop` 토큰이 있으면 `gameplay_context_review`로 따로 둔다. 실제 발화가 포함될 수 있으므로 삭제하거나 UI로 확정하지 않는다.
- 메일의 `name` 필드는 발신자명·라벨 검토로 분리하고 제목·내용과 섞지 않는다. `mail_review`에는 제목과 내용이 함께 있을 수 있으며 원본 숫자 필드만으로 본문이라고 확정하지 않는다. 이름표가 실제 발화자를 증명하는 것도 아니다.
- `ui_text.bin.json`·`ui_texture_text.bin.json`의 `text` 필드는 UI 출처로 표시한다. 단어 ‘버튼’·‘눌러’만 보고 일반 대사를 제거하지 않는다.
- `talk.bin.json`의 혼합 숫자 필드 `21`은 경고를 붙여 검토한다. 짧은 발화나 괄호 문장을 일괄 삭제하지 않는다.
- 한국어 없음, 품질 경고, 이름, 불명확한 출처도 `review-held.jsonl`에 원본 참조와 함께 남긴다.

반복 그룹의 기준은 **`ko` 열 정제 문자열의 정확한 일치**다. 후보뿐 아니라 이 열이 비어 있지 않은 전체 행을 대상으로 하며, 실제 언어가 의심되어 보류한 행도 포함한다. 검증된 한국어·같은 뜻·같은 발화·같은 일본어 원문이라는 판정이 아니다. source의 `sceneGroup`은 아직 검증 전인 문맥 후보이므로 같은 문맥/다른 문맥 그룹도 검토 보조 정보다. 모든 반복 행은 보존한다.

## 표본과 라벨링

최초 몇 행만 보는 대신 출처 ID와 seed의 해시 순위로 층별 표본을 고른다. 게임·분류 안에서 인물 언급, 분류 사유, 한국어 열 경고를 서로 다른 type의 층으로 관리한다. 혼합 숫자 필드 같은 드문 위험도 별도로 뽑으며 모든 행에 공통인 미확정 화자 라벨은 표본 층으로 쓰지 않는다. 인물 언급이 없는 행도 별도 층에 포함하며, 후보 전체를 연락처 인물 이름으로 필터링하지 않는다. 인물 언급 층은 발화자 라벨이 아니다. 이 표본을 전체 코퍼스의 정확도 추정치로 보고하지 않는다.

현재 원본은 발화자·청자·대화 순서를 복원할 연결 정보가 충분하지 않다. `speaker`, `recipient`, 시점은 미확정으로 유지하고 모든 행은 `trainingEligible: false`다. 검토자는 해당 원작 장면으로 돌아가 인물·상대·시점·분기·순서를 확인하고 근거를 기록해야 한다. 이후 검증된 장면 단위로 대화쌍과 모델 템플릿, 평가 분할을 만드는 단계가 별도로 필요하다.

실제 표본의 `dialogue_context_review`에는 발화뿐 아니라 줄거리 서술문도 포함되고, `name_review`에는 물건 이름도 포함된다. 경로 기반 분류의 한계이므로 각 행을 확정 대사나 확정 인물로 취급하지 않는다.
